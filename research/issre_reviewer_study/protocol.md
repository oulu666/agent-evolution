# 独立工程师能否借助证据台账选对下一步处置？
 
## 冻结范围和研究问题

2026-11-24。第一轮为三个匿名席位的小规模独立评阅。比较对象是同一题在三种信息条件下得到的首要处置。第一对照为 C 与 B，第二对照为 C 与 A。同时列出每位评阅者各条件的正确数、无法确定数和每题用时。英文稿沿用此前实证结果；独立评阅成绩须来自实际回收的答卷。

A 提供任务、通常的测试状态及最终输出。B 累加可获得的调用端点顺序及异常处理信息；无相应观察点时如实说明。C 再累加契约出处、推导、输入条件或中间记录。三个版本共享题干、操作选项和独立执行参考。案例文本是研究者对执行记录编制的诊断工单。C 提供的信息按题目取用，参与者无需外查资料。两个宽度案例只使用返回值即可核验，作为较少信息已经够用的对照。

## 分配和实施

第一轮固定最多三个不同评阅者。纳入有开发或测试经验、未参与框架设计、未接触本轮材料与答案、同意匿名研究使用判断的人。主持人先登记三个匿名顺序位，按事前固定的顺序 R03、R01、R02 各交给一人。只分发对应的单个 HTML 文件。避免向评阅者提供项目报告、其他人的题本、主持人资料和分组假设。只保存席位与答卷，不记录姓名。若机构有针对人员研究的审批要求，主持人应在招募前处理。

每人六题，每题只见一次，各信息条件两题。每一题在三个席位恰好各落入 A、B、C 一次。题序逐席位打乱，分配表由固定种子预先生成。独立作答，不查资料、不共议、不接收即时评分；开始前可退出。参与者选择一项首要处置，简述依据；无法判断可明确作答。浏览器计量题目出现到提交的可见时间，切换标签期间暂停。可见期间的走神、阅读和打字均计入，用时解释为作答耗时。一次连续完成，结尾自行下载答卷。刷新会重置当前席位的作答；如中断，记录情况，提前见过题目者不重做正式测量。

## 分析和封存

主结果为正确处置数除以该条件已回收的有效题数；“证据不足”在此指标计 0，并单独统计比例，保留合理弃答的理由。无任何人工资料时无正确率、弃答率或耗时。准确率衡量选中可执行参考处置的能力；不知道时弃答可以是对有限证据的合理判断。本轮不以事后理由覆盖冻结的单选主分。另列案例、条件、选择、理由及用时，标注措辞歧义和合理替代选择，作为解释性材料。

C 对 B、C 对 A 都按同一案例配对，列出改善/恶化/持平数及每题结果。不同人作答同一案例，每个人也看多个条件；这不是同一人的前后变化。用时以各条件中位数和逐题原值呈现；正确率与用时并列，不合并加权。优先检查普通通过题或明确违约题有无倒退，以及完整证据是否主要降低弃答但增加误判。三人按描述性先导结果报告，不计算十八个独立工程师样本的显著性，不外推工程时间收益。

每个席位最多纳入一份完整、符合条件的答卷。部分、中断、已知不合格、重复等情况单独登记数量及原因，保留原件。重复文件经核实只保留首次完整提交，出现不一致须先核对来源。少于三个有效席位时报告可用单元及缺失格，完整设计的结论保持未测。此轮不因中途出现预期结果而调整材料或追加席位。

[冻结清单](lock.json) 记录材料、参考答案、分配和计分程序的 SHA-256。主持人用 study.py 加答卷路径计分；明细输出可另存为 CSV。无答卷时程序只报告未测。只有 participants 目录中的单个题本适合分发，每个文件可独立离线打开。
