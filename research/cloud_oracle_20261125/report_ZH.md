# 一位契约信息能识别哪些错误？

[GitHub Actions 云端运行](https://github.com/oulu666/agent-evolution/actions/runs/45636732535)在 Ubuntu 24.04 上完成。运行前冻结的提交为 `36e8a2f5`。4 个项目、13 对源码修订各执行普通输入与边界输入，得到 52 条观察。26 个版本的调用步骤、状态、成功输出或异常类型均与此前保留的记录一致。两种候选共享这些调用，对每个版本分别评分。

| 每次执行后可用的判据 | 旧版告警且修复版通过（12 组） | 比粗粒度检查多检出 | 修复版告警（12 组） |
|---|---:|---:|---:|
| 调用成功状态 | 5 | 0 | 0 |
| 状态及粗粒度预期 | 5 | 0 | 0 |
| 状态及两输入的输出应相同／应不同 | 10 | 5 | 0 |
| 状态及返回结构 | 6 | 1 | 0 |
| 状态及关系、结构任一违约 | 10 | 5 | 0 |
| 状态及完整预期 | 12 | 7 | 0 |

关系判据保住全部 5 个基线命中，在 humanize 的 #218、#250、#254、#273 和 Rich 的 #3718 上各增加一次检出。结构判据新增的 Rich #3718 已被关系判据覆盖。排除 humanize 后，关系判据为 6/7、粗粒度检查为 5/7。主分析沿用同组代表 #250。若换用同组的 #240，关系判据降至 9/12，完整判据仍为 12/12。这两项敏感性检查表明增益的大小依赖项目和见证的选择。

**哪个例子解释了增益？** 在 humanize #254 中，冻结契约要求 60 秒和按零位小数处理的 59.5 秒都显示为 `1 minute`。旧版分别给出 `1 minute` 和 `60 seconds`。数值都等于 60 秒，类型也都是字符串，但两次输出违反了应相同的关系。在 Rich #3718 中，普通标题与蓝底标题应分别读到空背景和蓝色，旧版两者都是空背景。两种候选均识别了这个错误。

**哪些错误留了下来？** PrettyTable #356 的边框从普通样式的 `+` 变成另一字符，实际 `└` 和预期 `├` 都满足“不同于普通样式”。humanize #216 的葡语单复数也留下了相同的关系和类型。要区分这两种输出，需要边框连接方向或语言规则等更具体的依据。

**研究决策。** 保留输入关系作为独立验证的候选，结束返回结构作为额外模块的探索。本轮的“应相同／应不同”和返回结构均从已知预期抽取，主要结果测量的是精确答案被压缩后还能保留多少检错能力。下一次验证应在独立项目中先由修复前公开文档给出关系、冻结输入，再揭示修复与评分。需同时统计能够提取关系的任务比例、误报和相对规范示例的新增检出。此次没有测量 Agent 最终交付或工程师用时。
