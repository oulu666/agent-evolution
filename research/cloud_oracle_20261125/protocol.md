# 云端实验 · 精确答案可以压缩到什么程度

这是一轮已有见证的配对再执行。样本固定为此前复现的四个项目、13 对源码修订和 12 个缺陷组。主分析沿用 #250 代表包含 #240 的同一组，另保留 #240 的记录。两个输入与对应预期均沿用冻结脚本。没有新的盲测样本。

每个版本实际执行普通输入与边界输入各一次。所有方法共享这两条轨迹。每种方法先检查两次调用是否成功，再采用下列信息判断该版本是否违约。

| 方法 | 额外判据 |
|---|---|
| status | 仅调用状态 |
| coarse | 原有粗粒度预期，逐输入核对 |
| relation | 原有契约只保留一位信息，即两个精细预期应相同或不同。比较实际两个结果的关系 |
| shape | 仅保留两个精细预期的 JSON 结构，检查类型、数组长度与元素结构，对象还检查字段与子结构。数字统一为一种类型 |
| union | 关系或结构任一违约即告警 |
| full | 原有粗粒度与精细预期均逐输入核对 |

主指标为旧版告警且修复版通过的缺陷组数。另报修复版告警、相对 coarse 的逐组增减、两候选各自独有的检出，以及性状相同但内容错误的反例。保留执行失败并单列。新旧执行逐项对照实际状态、成功输出和步骤；异常比较异常类型，忽略实现相关消息措辞。按项目并发回放，两种候选在独立输出文件中并行评分。

本轮条件关系与结构由已有预期投影得到，用于测量压缩损失。每个项目均为已知见证，无训练或选参。若没有独有检出，停止投入对应机制；若有增益且未增加修复版告警，只保留为下一次无精确答案、独立契约来源验证的候选。公开报告给出源码提交、运行编号和可复现命令。
