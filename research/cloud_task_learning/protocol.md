# 一项任务怎样教会工具 Agent 选择完整计划

研究单位为用户提出的一个自然语言问题。Agent 必须选出查询列、聚合操作和筛选条件并执行，最终交付一份完整答案。三个候选分别改变决策知识的存储方式、学习信号和训练环境。使用轻量可重复的策略，隔离这些机制。研究假设是经验迁移或执行反馈可以改善未见表上的整任务交付。没有训练通用语言模型。

## 样本和资源

[WikiSQL 原始发布数据](https://github.com/salesforce/WikiSQL/tree/cffb423077756d04c1bac5bcd45167c86903fbcb)包含自然语言、表格和人工标注的查询。官方 train、dev、test 中按带固定前缀的 SHA-256 顺序分别抽取 768、128、256 张表，每张表只取问题哈希最小的一题。不按答案、难度或可解性筛选。三个集合互不共享抽中的表。公开基准不能防止既有领域知识，本轮不调用预训练模型。

各方法共享用户问题、表头和一次读表获得的单元格，可以选同一批至多 48 个计划中的一个并执行。候选生成器考虑六种聚合、原表中的字面值、无条件或至多两个条件；详细排序与边界见 plans.py。候选不含正确程序的题也进入分母。排名器超参数、干预和候选容量本轮固定。最终部署预算均为一次读表和一次所选查询；训练、造候选和离线评分的开销另记。

| 方法 | 如何获得整项任务的决策策略 |
|---|---|
| 规则基线 rules | 直接使用共享生成器的第一名 |
| 专家模仿 expert | 用完整专家计划标注正例，拟合特征到计划得分的排序器 |
| 经验记忆 memory | 检索训练集中最相似的去词值问题，迁移聚合与筛选操作骨架，再映射到新表。用训练计划，不训练排序器 |
| 结果学习 outcome | 训练时仅给实际表上的目标答案；执行各候选，将返回相同答案者列为正例 |
| 干预学习 intervention | 对训练表抽取部分行，再独立打乱各列，分别产生两个附加环境；只有三个环境都交付正确才作为正例。干预答案由离线专家查询生成，需要额外监督 |

后三种为候选。三种学习排序器使用相同的特征、逻辑回归和任务权重。对结果学习和干预学习而言，每题可有多个正例或零正例；全正或全负任务缺少排序信号，保留计数。专家模仿只在正确计划进入候选时有正例。两种学习信号的差异可能同时改变可用训练题数。

## 事先确定的判定

主指标为原始表中完整答案与专家查询返回列表一致的任务数；附报结构完全匹配，以及在同一题的独立重排并隔行抽取的数据上也答对的题数。后者是执行压力测试，无法证明所有数据上的语义等价。采用参数绑定的 SQLite 查询，数字及文本按类型归一化。本轮不提供 WikiSQL 全榜成绩。

先存档所有方法对开发和测试表的选择，再仅按开发集交付数选一个候选，同分看双环境正确数，再同分按表中候选顺序选。测试集一次性确认，同时公开其余臂的描述性结果。只有选中候选在测试集比专家模仿高至少 5 个百分点、同时双环境正确数不低，才进入后续方法研发。另报相对专家模仿的逐题赢、输、平，以及动作空间的可达上界。一次研发筛选通过后仍需新的独立任务验证。

复现用 Linux、Python 3.11 和[冻结云端配置](../../.github/workflows/cloud-task-learning.yml)，运行 `python research/cloud_task_learning/run.py /tmp/wikisql task-results`。
