# 主动设计训练环境能否提高未见任务的交付率

沿用上一轮 WikiSQL 数据哈希、768 张训练表、至多 48 个候选计划、学生特征和学习器。开发和测试分别取原哈希顺序中上一轮样本之后的 192 张和 512 张表，每表一题，题目选择规则沿用上轮。训练集重复用于控制比较，开发和测试表均更新。学生对每项部署任务读表一次、选一个计划、执行一次。

三种候选共享一个目标：借助离线教师给出的答案，减少原始表上碰巧正确的训练计划。原始表答案用于初始化一致候选集。每种基于答案的策略均有 768 次原始教师查询和 1,536 次额外教师查询。候选程序的本地模拟另行计费。完整专家步骤模仿单列，直接使用 768 份计划标签。不存在等价的答案调用数换算。

| 组别 | 训练决策 |
|---|---|
| expert | 直接模仿专家计划 |
| legacy | 上轮方案，依次抽取部分行、打乱各列 |
| random | 在新的八种环境中按每题固定种子随机抽取两种，无放回 |
| construct | 固定复制整表一次，再追加仅改变一个返回列的对照行 |
| adaptive | 每题两次。对每个可选环境模拟当前剩余计划的返回，优先选择期望排除计划数最高的环境，用教师实际返回过滤后重新选 |
| pooled | 拿相同总预算，每次在所有训练题间选期望排除数最大的“题目及环境”。每题额外 0 至 4 次，同分优先此前分配较少的题 |

新菜单的八种环境为整表重复、追加偶数行、追加奇数行、随机追加部分原行，以及四种保留行的单列替换。替换值来自同列其他原始记录，替换列根据候选计划的输出列顺序确定。旧行全部保留，原有的筛选命中不会消失。复制和替换可能破坏主键唯一性或跨列业务依赖，它们是受控学习环境。未见压力环境追加部分行，并从同一供体行替换至多两列。题目若在原表就无匹配，仍可能为空，因此另报原表有匹配记录的子组。

主动教师将尚可解释原答案的 n 条计划暂作等权。若环境把这些计划划为大小分别为 n_j 的返回组，期望排除数为 n − Σ(n_j²)/n。打分仅用候选模拟；选定环境后才执行教师查询。训练时保留所有已询问环境上的一致候选，沿用正负各半的题级权重、同一逻辑回归设置。按策略记录教师查询、候选模拟、实际保留数和训练进程 CPU 时间。

主指标为原表整项交付正确数；次指标为原表和保留原记录的压力表均正确数，另报专家结构匹配。先封存全部选择，再只用开发集对 construct、adaptive、pooled 选优；同分依次比较双环境正确数、上述候选顺序。由此选出的唯一候选在测试集须超过三种基线中原表最强者至少 26/512，且双环境正确数不低（基线同分取双环境较高者）。另报逐题赢输，避免按测试结果更换主候选。若训练标签更纯而交付无增益，停止在相同学生和动作空间内调教师选择权重。

复现入口为 `python research/cloud_active_teacher/experiment.py /tmp/wikisql teacher-results`。Linux 和依赖版本见[云端配置](../../.github/workflows/cloud-active-teacher.yml)。
