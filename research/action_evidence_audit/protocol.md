# 主工具、备用工具与探针的部署价值审计

2026-11-25。研究阶段为环境审计。先冻结真实工具、版本、任务、比较方法、成本与计分规则，再运行；冻结清单含完整代码及 CommonMark 0.31.2 官方案例的哈希。

## 工具与任务

Markdown 请求为将一段普通文档片段渲染成符合 CommonMark 0.31.2 的 HTML。主工具 Mistune，备用 markdown-it-py 的 commonmark 模式。选定九个普通排版章节，每章保留至多 240 字符、无尖括号或方括号的所有示例，按官方序号顺序分配角色。忽略块元素之间只用于排版的换行；核对元素、属性、行内空白和文本。小语料中不含额外插件任务。YAML 请求为按显式 1.1 或 1.2 指令读取一个普通配置值，核验 JSON 型别与值。主工具 PyYAML 使用可用的 CSafeLoader，备用 ruamel.yaml 使用 safe 的纯 Python 解析器并显式设置版本。后者是为保留版本语义选用的公开配置。成本评价只适用于这两个实现配置，不推断全部 YAML 后端性能。所有输入均是无副作用的小文档，未注入失败、延迟及备用配额。

Markdown 每章节及 YAML 每版本与词法类别内，序号除五余零归探针，余一归开发，其余归测试。YAML 的预期取自公开的 1.1 类型规则及 1.2 Core schema，预先逐项指定。不同版本下相同词面属于相关任务。旧版组合只为路由策略拟合开发任务；最终评价用另一批输入和较新的两个发行版本。旧、新版本以及配置和依赖的具体值见 measure.py；PyYAML 旧版 6.0.2、新版 6.0.3，ruamel.yaml 0.17.40、0.18.16；Mistune 3.0.2、3.1.3，markdown-it-py 3.0.0、4.2.0。无故障历史标签要求，正常结果全部保留。

## 审计一

实际分别执行 P、B。发布版、任务契约均公开。以目标为单位报告仅 P 正确、仅 B 正确、双正确和双失败；任一正确为事后最大正确交付数，双失败时暂缓。双正确时可由实测耗时选择较快者。部署基线直接 P 或直接 B，各自每次仅一次调用。无探针，亦无强制等成本补齐。分别报告正确、错误、暂缓和实际资源，不给等待或备用设置主观罚分。

## 审计二

每个任务的可用探针是同一项目、同一公开类别中的一份异输入校准样例。用输入词法 token 的 Jaccard 相似度选择，按长度差和样例编号打破平局。有公开独立期望的探针可在主或备上执行。两次结果的组合包含这个菜单内最多的可得证据。考察以下事后界：只看类别；类别加最近探针身份；类别加两条返回的正误；类别、身份和两条正误。每组择正确交付最多的动作并加总；另算在样本内坚持零错误能够覆盖的最多任务。按相同任务统一评分。上界读取标签，不能作为可部署方法。身份相同、工具版本相同且确定时，探针返回可能只复述一次可缓存的查询。这正是身份对照的目的。上界只针对定义的有限菜单和给定特征；不排除新的目标相关探针能提供额外证据。

可部署对照包括直接 P、直接 B、按类别路由、再加探针身份路由、主探针通过用主否则切换、备探针通过用备否则用主，以及两个探针驱动的经验路由。学习策略只使用旧版开发输入：每桶取正确数最多的动作；同分时先比较错误，再比较实测执行时间；未见桶退回类别规则。若两个工具开发结果均失败，允许暂缓。新发行版不提供训练标签。不引入 Qwen，调用方已明确给出任务类型；在线路由代码计时，模型推理调用为零。本轮不验证自然语言路由能力。

每个输入与工具配对执行 1 次暖机、5 次随机交错计时，用中位数，检查六次结果一致。单独记录服务和探针判定耗时。部署轨迹使用实际测得的中位数重放；新任务冷缓存与同版本整批共享精确缓存分别计数，目标提交从不作为探针缓存命中。一次性装载和离线训练不计入每次请求。报告本机暖服务成本，保留原始计时；不以少量微秒差推断外部 API 成本。

## 继续条件

只有事后动作上界相对零探针静态对照留下实际空间、并且有限菜单在控制公开特征后提供额外区分，才进入非对称证据估计。若主要收益是一个已知版本的重复查询缓存或公共输入规则，先停在环境审计。分项目判断质量和成本的取舍，特别报告备用全对但更耗时的可能性。
