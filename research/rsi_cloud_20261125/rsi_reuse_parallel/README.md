# 跨任务舍入反例迁移：稳定时省一次尝试，语义漂移时不稳

候选机制用舍入边界签名复用其他任务的成功与失败：比较数字是否在舍入边界、符号和保留位奇偶，允许迁移同一部署标签下、但来自其他任务语境的历史证据。强对照也具有同一套 Decimal 符号语义，只复用同一语境和部署标签的历史。最大预算是 2 次，每次真实执行 Decimal 加对应 CSV 或 JSON 往返，再由独立 Fraction 参考验证。各策略共享八条源记录。迁移目标包括 plain 与 JSON 槽位，源数据包括 CSV 与 JSON；这只是跨包装和语境，不是跨不同舍入算法或开源项目。

## 首次调用成功数

| 语义设置（各 480） | 只用默认规则 / 精确缓存 | 同语境语义迁移 | 加边界签名跨语境 |
|---|---:|---:|---:|
| 稳定政策，共享部署标签 | 344 | 447 | 461 |
| 可见部署标签变化 | 332 | 332 | 332 |
| 隐蔽政策变化，标签未改变 | 332 | 279 | 277 |
| 共享标签下，不同语境各自有政策 | 341 | 442 | 418 |
| 总计（1,920） | 1,349 | 1,500 | 1,488 |

两次预算所有方法均 1,920/1,920 正确，无错误交付。总调用同语境 2,340，跨语境 2,352。稳定条件跨语境所得 14 个首轮成功在混合语境失去 24 个；隐藏切换里直接用默认值反而更强。可见标签变化回退到冷启动。不存在真正精确缓存键命中，故不能推广到重复请求多的负载。

独立验证审计 3,456 个记录、24,192 次实际标准库调用对照 Fraction 参考；每条记录在所测七种模式下最多有两个相邻数值结果。不再运行两次预算下的新搜索算法。要让跨语境迁移成为候选机制，需要可观测的“两个语境使用同一舍入函数”的证据，仅分歧签名相同无法保证迁移。它目前只提供条件性信号和一个触发负迁移的反例。

分母按预宣告种子生成，所有种子在四个受控设置复用，同一种子内的任务不能算独立真实缺陷。算法只用 `Decimal` 有限的模式族，不涉及任意数值工具函数。[Python Decimal 舍入定义](https://docs.python.org/3/library/decimal.html#rounding-modes)。初始实现中的加常数权重修改见冻结备注，不把两个权重版本当独立重复。

复现：`sha256sum -c rsi_reuse_parallel/LOCK.sha256`、`python rsi_reuse_parallel/pilot.py --out rsi_reuse_parallel/results_v2`、`python rsi_reuse_parallel/certify.py`。主要公开材料为代码、冻结口径和汇总，不需要发布每条记录。
