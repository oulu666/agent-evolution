# F2：不可逆格式转换前保存最小来源信息

实际 openpyxl 生成/重读 XLSX，标准库 CSV 写出/重读。自然接口限制是 CSV 导入只接收 `item_id,cents` 两列，不允许混入元数据。共 12 个受控台账 × 4 类用户要求（表格、金额显示、可访问性标记、完整的本实验属性），核对传回的数据、数字格式、粗体、工作表标题和批注。不是历史真实用户数据，也没覆盖 Excel 的全部格式特征。

| 允许 CSV + 独立元数据时 | 正确/48 | 错误 | 总交付字节 | 完整重建 |
|---|---:|---:|---:|---:|
| 直接 CSV | 21 | 27 | 1,296 | 48 |
| 本实验四属性全记 | 48 | 0 | 5,004 | 48 |
| 按需求字段投影 | 48 | 0 | 2,882 | 48 |
| 按字段投影并略去重建默认值 | 48 | 0 | **2,211** | **48** |
| 穷举候选子集，取最短能复原者 | 48 | 0 | **2,211** | 241 |

主成本是 CSV 和 UTF-8 紧凑 JSON 字节之和；未纳入额外渠道启动开销。Native XLSX 保留 48/48（257,224 字节），但不是严格 CSV 接收口可用的同任务策略。若只准 CSV，已知哪些任务要求不可传的强门控只交付正确的 21 个并暂缓 27 个；单纯直接交付给出 27 个错误。独立反例脚本执行 12 对金额样式不同但 CSV 字节完全相同的实际 XLSX：单靠 CSV 不可能完整恢复显示样式。

穷举得到的每个最短 sidecar 与简单规则逐字节一致；固定字段独立加默认的条件下，没有算法创新余量。若接口禁止独立渠道，则不能靠优化把已经丢失的信息恢复出来；需要用户允许保存对应元数据、改变合同，或显式暂缓。值得找的后续是多个相互作用的不透明元数据决定联合可恢复性，而强字段规则在实际接口里确实不能适用。不能把受控属性筛选答案写成领域无关的最小储存法。

复现：Python 3.12、openpyxl 3.1.5。运行 `sha256sum -c LOCK.sha256`、`python pilot.py --out results`、`python certify.py`。

复跑说明：原生 XLSX 字节数会随 ZIP/文档时间戳和压缩而小幅波动；CSV 与 sidecar 字节数、正确性和重建次数需一致。原生路线不是严格 CSV 接口的候选。
