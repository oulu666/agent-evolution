# O1：真实软件图标上的固定锚点失效
**结果：不立项。** 使用 ezdxf 发行包自带的五个 64×64 图标。Pillow 执行事先确定的几何变换、反相、RGB 循环；被检验的是已有 J1 思路在真实输入上的修复失败，不是 ezdxf 历史缺陷或生产事故。完整 64×64 RGB 字节仅用于独立验收，策略每次只向参考端读一个目标像素。源码侧真实可读的整幅待修图片给所有方法同样权限；有限组内的预测用数组索引计算，不将其当作实际 Pillow 修复调用。
  
筛查固定锚点：左箭头、右箭头、跳转书签三个失败，复制、搜索图标两个通过，未补样。三个失败在同一九点记录下分别有 5、3、2 个不同输出仍与全部读取一致。以固定序号猜测因此会错，简单改为证据不足就暂缓也不能完成交付；这是固定观测投影的问题，不是完整 PNG 无法辨识。

| 做法（同三案） | 完整恢复 | 错误 | 暂缓 | 目标读数 |
|---|---:|---:|---:|---:|
| 固定九点 + 直接分解（原对照） | 0 | 3 | 0 | 27 |
| 按剩余变换贪心信息熵（强对照） | 3 | 0 | 0 | 5 |
| 自适应按 distinct 输出类最小化最坏分支 | 3 | 0 | 0 | 5 |
| 批量固定测试集：贪心覆盖不同输出的区分对 | 3 | 0 | 0 | 5 |
| 不用标签的整图空间/颜色显著性先验 | 2 | 0 | 1 | 13 |

三条候选代表不同选择机制，而非调参：在线按最坏后果选观察，离线一次设计区分测试集，不建目标结论模型就按图像结构排位。显著性在左箭头连续看局部后仍有 12 个可能输出，淘汰。最坏分支和批量法都无等预算增益；三案每案的读数分别同为 2、1、2，虽然选点可能不同。全部筛查对象均有 48 个不同输出，尚未出现变换等价类折叠，不能说已验证按输出归类的特有收益。批量计划可保留作下一轮对照，但未测通信轮数/延迟，不宣称效率优势。已有主动分裂方法相关：[GBS](https://doi.org/10.1109/TIT.2011.2169298)、[Decision Region Determination](https://proceedings.mlr.press/v33/javdani14.html)；这些原型不能凭目标变化声称新算法。

151/240 个计费动作（包含筛查及验收），CPU 单线程，无 GPU、模型 API 或付费资源。此次结果仅一个软件图标族、人工注入、有限菜单、无噪声观测；不当作独立验证。下一轮换机制：优先筛真正公开的功能异常，要求固定观察下出现多解释，且强文档/原生/贪心方案在同信息、同预算下确有剩余失败；没有即记为筛查未通过，不再加相似图标。若只能复现程序级控制案例，明确这一边界。
