# Pillow 文档图像修复表达式合成：准入实验

**结论：扩大操作语言能提出旧菜单没有的组合；用语义反向投影可以减少执行，但这不是新的核心合成机制，也没有优于简洁的人工规则。**

## 机制与对照

用户任务是导出满足尺寸、颜色通道和五个受保护像素条件的 PNG，不能篡改原图以硬凑校验。源图为生成的 RGBA，使用真实 Pillow 旋转、镜像、边框、裁切与白底透明度处理，实际编码并重新读取 PNG。在最多四个操作的同一语法内，合成器把受保护终点像素坐标反向投射到原图或已知边框色，只有符号计算符合契约才完整执行。独立 NumPy 实现生成目标，由单独全图对比评分。表格中的预算只针对 Pillow 实际执行，不把符号推理当免费算力，另报表达式枚举量。

| 策略 | 正确 | 错误 | 暂缓 | 真实执行 |
|---|---:|---:|---:|---:|
| 旧菜单（原子操作与 3 个固定宏） | 32/56 | 0 | 24 | 424 |
| 同语法、预算内朴素枚举 | 16/56 | 0 | 40 | 680 |
| 同语法、尺寸和通道先剪枝 | 48/56 | 0 | 8 | 152 |
| 受保护像素反向投影 | 48/56 | 0 | 8 | 48 |
| 手写透明度、边框和几何顺序规则 | 48/56 | 0 | 8 | 48 |

合成与尺寸剪枝均考察 17,824 个表达式变体，手写直接规则考察 48 个。基于实际执行的比较，合成较尺寸剪枝少 104 次（68.4%），并非省去相同比例的总时间；手写规则从完整的人工可读目标规格及已知操作语义直接构造，具有相同调用数和更低枚举开销；它是有额外语义知识的工程参照，不是同信息条件下的主要对照。八个暂缓都属于语法故意不含的缩放操作。样本是七种目标、各八个源图重复，不是独立真实项目或历史工具缺陷。实验未测试独立作者编写的复杂修复规格。校验脚本穷举本 DSL 在两张选定尺寸图片上的实际前向轨迹，比较反向投影和真实像素。

现有 [FlashMeta](https://www.microsoft.com/en-us/research/wp-content/uploads/2018/01/oopsla2015-flashmeta.pdf) 已用算子逆语义传播约束；本文仅用可手工定义的算子复现其思想。下一步若要尝试机制创新，不能只是换成图像：关键是面对文档未完整给逆语义时，能否从独立实际观察学习有效而保守的逆关系，并在同操作语法下击败可获得的直接基线。

复现：Python 3.12、NumPy、Pillow 13.0.0。运行 `sha256sum -c rsi_synth_next/LOCK.sha256`、`python rsi_synth_next/pilot.py --out rsi_synth_next/results`、`python rsi_synth_next/certify.py`。
