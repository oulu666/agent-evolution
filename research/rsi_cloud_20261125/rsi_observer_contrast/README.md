# 对观察点同时验证任务敏感与干扰稳定

真实 `lxml` 导出、序列化和重读账单 XML。自动枚举叶文字和属性，方法不预指定观察点。每个设置下，所有策略得到相同的 8 个完整校准产物（一个二值任务干预 × 两个二值表示/元数据扰动）；在新的账单金额和标签上再执行同样的 8 个固定测试文档。测四类各 32 个生成种子：干净、仅组合扰动暴露的代理、没有合法单字段、未标记语义变动。独立期望是该账单是否增加应计金额，评价观察点的变化是否正好跟随这个预期，不评价其数值数据本身正确。不是独立真实缺陷。

| 方法 | 正确选择 | 错误选择 | 暂缓 |
|---|---:|---:|---:|
| 仅选能区分任务干预的观察点 | 0 | 128 | 0 |
| 在锚点单独验证两种扰动 | 32 | 96 | 0 |
| 同预算、全交叉对照的平均损失 | 64 | 64 | 0 |
| 同预算、全交叉精确事例门控 | 64 | 32 | 32 |
| 拆成任务敏感和干扰稳定两组门控 | 64 | 32 | 32 |

联合代理的 32 个实例在边际对照全部误选，交叉验证全纠正。不可观察的 32 个实例严格法全部合理暂缓，但更强的全交叉基线完全相同。未标记变动时，严格门控选中的 32 个点全部在新环境漏报（128 个任务信号漏检），说明旧校准不能替代重新检测或版本边界证据。两种严格法零 nuisance 错报；这不表示因果泛化。

在这个有限模型，两组门控与穷举全部 28 对数学等价：同语义内容的表示扰动保持观察值不变，再要求同表示下两种语义得到不同观察值，传递性已推出跨表示的异语义观察也不同。只比较 16 对而不改变 API 调用数。当前的 8 文档全因子设计需要已经知道干预轴，轴数增大时成本指数增长。[MR-Scout](https://doi.org/10.1145/3656340) 说明变形关系检查与合成早已有工作，不能把显式对照本身当核心创新。真正待验证：能否在完整对照不可得时，自动识别最低成本但揭示交互的干预；还须独立验证真实工具变更。

复现（Python 3.12, lxml 6.1.1）：`sha256sum -c rsi_observer_contrast/LOCK.sha256`；`python rsi_observer_contrast/pilot.py --out rsi_observer_contrast/results`。
