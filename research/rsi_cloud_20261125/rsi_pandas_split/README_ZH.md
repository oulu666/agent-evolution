# RSI：换版后的局部状态拆分

**找到了真实的状态合并失效，但局部算法与标准最小改动基线打平。**

按 [pandas 3.0 发行说明](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html#consistent-copy-view-behaviour-with-copy-on-write)，Copy-on-Write 使写入取出的 Series 不再修改父 DataFrame。实跑 pandas 2.2.3 和 3.0.0。受控应用任务是更新草稿或一列挂接数据：草稿只改自身，挂接列要同步父表。创建时记录从父表取列还是显式深拷贝；两者编辑前父子数值和 dtype 完全一致。2.2.3 原策略“只写子 Series”满足两段历史。3.0.0 则必须分开：挂接历史只有显式写父子两个对象通过；草稿只允许写子对象。在只看数值和 schema 的观测约束下，不存在覆盖两者的同一个动作。这是上游记录的设计变化，不是 pandas 3.0 的 bug。

## 方法与结果

局部拆分在共享有限语法内找二分特征，优先少改旧动作；冷启动独立求解；另以同信息的普通最小改动精确枚举作对照。训练反例每条需要两次真实动作执行，分别检验两个动作是否正确。评价时根据创建事件和预定父子数据目标核对真实结果；运行时不读答案。以下主设置为两条反例、四次训练执行，复跑 96 个变化数值、选择方式与表宽的场景。并非 96 个独立迁移，也未留出新历史类型。

| 策略 | 新版正确 | 旧版正确 |
|---|---:|---:|
| 不改旧控制器 | 48/96 | 96/96 |
| 局部拆分 | 96/96 | 96/96 |
| 同语法冷启动深度一 | 96/96 | 96/96 |
| 普通最小改动精确枚举 | 96/96 | 96/96 |
| 专家保存一个来源位 | 96/96 | 96/96 |
| 用 NumPy 测量当前内存共享 | 96/96 | 96/96 |

最后一项每个版本多做 96 次只读测量。只限编辑前、所测数组及这两种构造；不是通用的 pandas 别名判据。说明进一步开放观测后，当前信息也可能补足历史。

**单反例陷阱：** 只先看到挂接列反例，默认特征顺序中局部拆分双 96/96，冷启动选择全局双写、两个版本各 48/96。穷举四个特征的全部 24 种顺序后，双 96/96 只在 6 种成立，其余 18 种旧版 72/96、新版 48/96。普通最小改动枚举给出相同汇总结果；只先看草稿，一律旧版 96/96、新版 48/96。该敏感性检查在主试验后增加，没有改动冻结源码。

## 研究判断

已经验证“原先同一策略可用，升级后必须区分历史”；没有证据表明局部算法比强对照更稳定。[增量自动机学习](https://www.csc.kth.se/tcs/publications/2011/Lic_muddassar.pdf) 已有复用旧状态等价关系的思路。下一轮值得集中检验：在**所有获准的当前只读信息上都分不清、且历史里哪个字段重要也不明显**的案例中，能否主动选第二条能打破歧义的反例，同时超过同权限的信息增益与标准 Mealy 细化？优先入组真实状态变化，不把特征第一的位置写成算法贡献。

## 复现

Python 3.12.14、NumPy 2.3.5、pandas 2.2.3/3.0.0、python-dateutil 4.0.0、pytz 2026.6、tzdata 2026.6。安装旧版到运行环境，下载 3.0.0 wheel 解包到独立目录，不覆盖旧安装。脚本断言两子进程版本。

```sh
python -m pip download --only-binary=:all: --no-deps pandas==3.0.0 -d wheels
(cd wheels; sha256sum -c ../WHEEL.sha256)
python -m zipfile -e wheels/pandas-3.0.0-*.whl release
python pilot.py --new release --out results
python sensitivity.py --new release
```

冻结哈希需在上一级执行 `sha256sum -c rsi_pandas_split/LOCK.sha256`。wheel SHA 针对本次 Linux x86_64 CPython 3.12 构建，其他平台需另记录。
