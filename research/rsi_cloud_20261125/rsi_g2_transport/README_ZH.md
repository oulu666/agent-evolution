# G2：用源端干预证明的关系迁移修复

在真实 SQLite 3.53.1 和 pandas 2.2.3 上执行双键左连接。[pandas 的 merge 文档](https://pandas.pydata.org/docs/reference/api/pandas.merge.html)明确说明空键之间可能匹配；[SQLite 文档](https://www.sqlite.org/lang_expr.html)区分普通等号和 NULL 安全比较。任务可能允许某些空值组合匹配而禁止其他组合，不能把一律拒绝或一律允许当成业务真值。

**机制：** 只看源端公开左连接结果，构造四种左键缺失形态，先观察控制，再在右表用带标记数据批量触发匹配。新增标记对应允许的缺失形态。迁移到目标时使用双方共知的字段映射，只从 pandas 右表排除不允许匹配的键形态，不删除左表行，也不把空的业务字段误认为空键。完整规则可以表达“两字段同时为空可匹配，只有一个为空却不匹配”这种单轴无法表示的约束。

预设的有限语言：只有同值键才可能匹配，行为只依赖两个键字段的空值形态，且无空值时一定允许。用真实查询恢复了全部 8 套规则，各用了 2 次源端执行，共 16 次；每套注入 4 行，共 32 行。每套在 12 份改名、重排并包含重复键和未匹配键的 pandas 输入上验收。独立的袋语义判据对比每个左、右行 ID 的匹配及其次数，不以照抄源端文件为通过。补充负对照把两边源端非键负载都改为非空，16 次额外源端运行仍恢复全部 8 套规则。

| 方法 | 可按单轴解释的 48 份 | 存在联合规则的 48 份 | 总正确 / 96 |
|---|---:|---:|---:|
| pandas 默认连接 | 12 | 0 | 12 |
| 通用 SQL 风格，禁止所有空键匹配 | 12 | 0 | 12 |
| 每个字段单独学习，双空结果按 AND 合并 | 48 | 0 | 48 |
| **源端干预证书 → 目标修复** | **48** | **48** | **96** |
| **同证书，原生 pandas 掩码** | **48** | **48** | **96** |
| **同证书，显式规范 IR 哈希连接** | **48** | **48** | **96** |

强原生策略和规范 IR 收到同一实际源端证据，不知道预设的隐藏规则，三者同为 96/96、一份报告执行一个目标工作流，无额外证据调用差异。规范 IR 并非直接调用 Python 结果当真值，独立跑了一条通用按键索引的实现。所有样本都是受控业务规则，不是 96 个历史缺陷。已知映射、有界候选语言、成本按接口运行次数统计，不能推断更宽键组合的开销，也没有测墙钟延迟。

**决定：** 干预证据能跨引擎保存复杂匹配关系，单轴抽象丢失的关系确实会错。但新编译薄层未超过已有原生或规范化做法，不立项。若进一步研究，应先建立跨目标复用的源端证据成本优势，或验证未知键维度下无需全枚举的可证机制。
