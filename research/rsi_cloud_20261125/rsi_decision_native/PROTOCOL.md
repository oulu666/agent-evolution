# Continue / verify / rollback, native-comparator admission test

Frozen before execution. One staged functional operation: create a temporary inventory reservation in an isolated SQLite database. Contract: keep only nonnegative quantities, valid warehouse references, and, if a task supplies a quota, aggregate warehouse bookings not exceeding the quota. Do not retroactively modify the existing reservation. No real services or security behavior.

Environment declares (1) whether it enforces FK at COMMIT, (2) whether the business quota applies, (3) whether the exact pre-reservation total from this same transaction snapshot is available as part of staged feedback. The planner sees proposal quantity, quota, whether FK is engine-managed, success/failure of staging, and exact snapshot only when explicitly present. Neither actual parent existence nor hidden used quantity is a method input. All techniques operate on the same public staging interface. COMMIT failure is an ordinary protected rollback outcome, not a successful delivery. Business-quota verification and explicit FK verification are charged separately, aggregate and FK cost one each. Fixture setup, staging, final action and independent audit are separate from verification budget. Classify successes and false acceptances independently from delivered row existence. Report operation family and branch counts.

Candidate: map obligations to proved-good, proved-bad, guaranteed rejection at COMMIT, or unresolved. Roll back on a proof of failure, otherwise explicitly verify unresolved obligations and continue when clear. Strong native: use SQL CHECK and deferred FK atomically, and directly apply the explicit inventory arithmetic bound when exact snapshot is visible; otherwise verify aggregate before COMMIT. Additional policies commit after staging or verify both contracts explicitly. Primary outcome durable final state correct, secondary verification-count reduction when equally correct. Hold structured mixed cases aside from source cases, introduce new IDs/quantity ranges and both obligations jointly. This is a predeclared compositional holdout of designed fixtures, not blind real defects. Freeze if strong native ties or wins. Exact correctness for one finite configured workload only.
