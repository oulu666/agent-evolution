# H2 protocol (frozen before execution)
Hypothesis: coalescing source writes by row-level semantic contribution can avoid unnecessary SQLite report projections without publishing stale output. Controlled fixtures, real SQLite and deterministic CSV + gzip exports. Baseline A is a source-hashed DAG with canonical output early cutoff; B is stronger and hashes exact canonical per-region SQL projections before running downstream CSV+gzip only on changed output. Candidate C compares a map of old/final row contributions to identify dirty regions, then runs exact projections only there and retains canonical early cutoff. All methods receive the same batch deltas (absolute writes with old values via a real SQLite update trigger); C additionally accounts for Python applicability work (row reads/coalescing/canonicalization) and no coarse elapsed-time benefit can be claimed unless actually seen. The output oracle full-rebuilds all regions after each batch outside timed blocks, compares compressed bytes, and expires any method with even one stale completed export. No policy reads oracle. Freeze four workloads (metadata edits; back-and-forth within batch; mostly substantive sparse edits; mostly substantive dense edits), six seeds per workload, 36 batches per seed, 16 regions and 640 SQLite rows, all chosen before run. Compare projection count, gzip builds, elapsed including writes and trigger journal, plus C's number of applicability rows and contribution evaluations. Report medians over 6 seed histories; efficacy bar: zero stale, lower projections than B on all workloads and >=15% median time improvement on >=3/4. Seeds are fixture replicates, not independent applications; known-bounded controlled design, not historical data.
