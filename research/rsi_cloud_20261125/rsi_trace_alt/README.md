# 双向中间产物拼接：淘汰一个候选机制

工具串行执行四个文本归一化模块，顺序影响最终文档。每次调用返回各阶段完整文档。算法以历史中实际观察到的“模块、输入文档、输出文档”作为边，沿输入向前检索，并从目标文档反向检索已观察到的后缀；优先尝试尚未连通、但两端已有较多证据的顺序。只能拼接完全相同的完整文档状态，不求函数逆、不假设操作可交换。候选必须实际执行成功，不靠预测记分。反向全路径证书和前向全路径证书在同一张精确图上等价（程序逐次断言）；反向机制只能改变下一次调用的排序。

| 策略 | 校准通过 | 同时通过校准和另 8 份文档 | 校准通过但未全部迁移 | 探索调用总数 |
|---|---:|---:|---:|---:|
| 同种子打乱顺序 | 203 | **85** | 118 | **739** |
| 只看前向已知路径 | 149 | 68 | 81 | 902 |
| 双向中间产物拼接 | 154 | 71 | 83 | 888 |

分母均为 240 个生成 fixture。每个 fixture 的三个策略共享同一模块映射、真实顺序、首个候选和候选排序，每次最多六次调用（每次四个模块）。计入上表的为探索调用；独立评分使用的参考执行和选中顺序的离线验证不计入预算，各方法采用同一标准。确定性回放，不使用 LLM/API 或正式留出项目。

双向与前向的配对结果是 68 同成功、169 同失败、3 仅双向成功、0 仅前向成功。它比前向多解决 3 项，却比同预算打乱顺序少解决 14 项，而且总调用更多。**不把这一机制推进为核心算法。** 单个校准文档存在大量可接受的顺序，但这些顺序不一定在新文档上等价；仅提高校准命中不能说明稳定进步。下一轮若继续本方向，应优先检验“花一次预算区分多个已通过的修复”而非继续增加拼接启发式，并保留随机顺序作控制。

## Replay
Python 3 标准库；在本目录运行：

    python3 pilot.py > replay.json
    diff -u aggregate.json replay.json

性质和边界：归一化是可复现的普通文本处理，公开文档及八份评分文档由同一生成族产生；不能外推到真实接口、模型自进化、企业缺陷或全新软件。实验未测逐文件运行延迟。完整设定见 PROTOCOL.md。
