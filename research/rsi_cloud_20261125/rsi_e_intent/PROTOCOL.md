# Intent questions over real functional APIs, frozen before execution

Controlled limited-answer study. No actual users, messages, LLM calls, or claims about reading natural-language intent. Each task has one of a finite list of equally probable private outcome rules. The public task states a desired report, but omits one or more preferences. A simulated consistent user chooses expected concrete preview outputs from that private rule; only question responses, not private intent indices or true job outputs, reach the decision policy. Actual Python Decimal quantization and SQLite ranking execute all candidate semantics. Decimal policies combine four rounding modes and signed/clamp credit handling; SQLite three rank conventions and keep/drop incomplete-score policy.

A permitted question asks for one miniature example's correct result (one amount or up to four jobs), produced independently of the complete requested report. Up to one question. Each policy gets the same legal previews, finite hypotheses, prior and summed costs: wrong delivery 1, abstention 0.35, question 0.10, correct delivery 0. User effort/time not measured. We count abstentions separately from wrong outputs. A vacuous false-ambiguity question is when all remaining intents yield an identical target output. Verify query responses come strictly from the intended hypothetical policy. Oracle correctness is exact match of the whole intended report, not semantic name or implementation choice.

Candidate ranks questions by count of output-disagreeing hypothesis pairs that the response would separate. Strong baselines: full-intent entropy; exact one-step task Bayes over the same previews; no question Bayes; native default without oracle; no-cost difference in chosen candidate input-output methods. Candidate, entropy and exact Bayes all apply identical ask/no-ask cost gate after selecting their best proposal. For perspective, a task-result oracle is a ceiling outside the miniature-preview interface (can choose the desired full report directly). All main counts aggregate six target templates per library, along with six transformed targets using new values/keys and score patterns. Paired scenario counts are realizations of author-defined intents, not independent participants. Require no aggregate cost increase and no more wrong deliveries than exact one-step Bayes for feasibility, but a tie never implies algorithmic novelty. A strict failure to beat generic entropy in both libraries freezes the mechanism.
