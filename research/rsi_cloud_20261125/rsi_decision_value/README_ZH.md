# D1：分解估计复查价值（未过准入）
在云端用 Python / NumPy 跑 4×384 个受控情景，执行 Decimal、NumPy、datetime 和 statistics 的真实运算，兼容修复候选和成本模型由实验构造。按 API 留一，不使用最终任务与复查结果作输入。

候选算法不直接学习“该选哪个动作”，而估计：候选交付出错概率、出错时复查能抓住的概率，以及正确时复查误触发回退的概率。把三者和任务给出的成本合成接受、复查、回退的预期损失。误交付的损失设为 8 时，得到下列留出结果（越低越好）：

| 方法 | 总成本 | 误交付 |
|---|---:|---:|
| 分解估计 | 2444.25 | 142 |
| 置信度 + 固定检出率 | 2481.25 | 147 |
| 联合结果 Ridge | 2484.50 | 146 |
| 直接成本 Ridge | 2498.75 | 148 |
| 预览规则 | 2506.00 | 140 |
| 始终回退 | 3842.00 | 0 |

分解估计总成本比最低成本对照低 1.49%，但只在 Decimal 和 NumPy 胜过每一种对照；两者又都是舍入任务，不能视为两个独立的成功机制。datetime 和 statistics 的简单规则分别得到 429 和 378.75，优于候选的 473 和 513。误交付惩罚为 4 时，候选与联合 Ridge、固定检出率均为 1545；惩罚为 16 时，联合 Ridge 2897.5 反超候选 2912.5。未达到事先的 3/4 过线条件，不据此微调小模型。决策成本是模拟单位，不是运行时间。

复现：`python scout.py > replay.json && diff -u aggregate.json replay.json`（Python 3.12、NumPy 2.3.5）。`sha256sum -c LOCK.sha256` 核对执行前的协议和源码。Ridge 是统一实现的对照，不是对 ICML 论文实现的复现。
