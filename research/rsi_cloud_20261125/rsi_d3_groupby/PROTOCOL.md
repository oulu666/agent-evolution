# D3 observed-groups historical admission, pre-run
Pandas changed groupby observed from False to True in 3.0.0 (GH 51811), per its [official release note](https://pandas.pydata.org/pandas-docs/stable/whatsnew/v3.0.0.html). Run 2.2.3 and 3.0.0 against the same generated categorical sales ledgers. These are synthetic task fixtures applied to real release behavior, not independent historical mistakes.

Three preregistered user requests: sparse (actual activity), complete (all valid categories including zeros), subset (requested roster, including zero counts, excluding out-of-scope activity). Freeze three families of category cardinalities and alternating row order/label variations. A=keep current 3.0 defaults; R=rerun old version defaults against identical initial data, not destructive rollback. N=documented explicit observed=True/False given the request, using reindex for published requested roster. A and R do not alter their defaults in response to the request. N is enabled only when the task contract is known, i.e., same evaluated goals and ordinary public API. Score against a separately implemented pure-Python tally; check both absence/presence and values, and exact version. Include cases with missing categories by design and an all-observed control. No version-selection labels provided to a learning system.

Report success by contract and both-fail counts, full-pair audit calls vs A-first/R-first (at unit check costs, after recording marginals as diagnostic). Implement executable short-circuit on fresh copies, not just accounting. Compare to native correctness and native call counts. Also report original fixed cost model (unit bad delivery; verify=.35; defer=.35 on both fail) for diagnostic comparison only, distinct from experimental calls. All candidate actions verified on case fixtures, no held-out learning here. Go only if known native clause is insufficient on at least one case that combined verification handles, or a real contract cannot be learned from equally available task information. Otherwise this shows a boundary: default routes can complement while native task semantics remove any gain.
