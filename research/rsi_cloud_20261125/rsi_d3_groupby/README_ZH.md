# D3：在 pandas 实际版本上检验配对核验
pandas 3.0.0 将分组默认的 `observed` 改为 `True`。云端执行 pandas 2.2.3 和 3.0.0，用独立 Python 计数器检查分类账簿结果。72 个任务输入是受控生成的夹具，只有 pandas 的版本行为来自真实历史，不代表 72 起历史问题。版本依据：[pandas 3.0 发布说明](https://pandas.pydata.org/pandas-docs/stable/whatsnew/v3.0.0.html)。

| 交付契约 | 3.0 默认 | 2.2 默认 | 两种默认择好 | 按契约用 API（任版本） |
|---|---:|---:|---:|---:|
| 只要发生过的活动 | 24/24 | 12/24 | 24/24 | 24/24 |
| 遗漏分类补零 | 12/24 | 24/24 | 24/24 | 24/24 |
| 指定名册且遗漏补零 | 0/24 | 0/24 | 0/24 | 24/24 |
| 总计 | 36/72 | 36/72 | 48/72 | 72/72 |

两种默认行为确实互补，都有独自成功的 12 例，但显式传 `observed` 并在指定名册时 `reindex`，只需一次聚合就能正确交付，不需要在新旧版本间试探。剔除构造得更严格的名册层也不改变结论：显式原生仍是 48/48，一次聚合。

执行层面，短路核验从单独重建的一致输入执行：先走任一默认版本，成功则跳过另一个；两种顺序均执行 108 次而非全配对的 144 次，得到完全相同的「两种都失败」标记。它节省的是实验核验调用，不是量得的耗时；也不等于学习型算法获益。若任务契约明确，分层已有最优默认方向，而原生实现还覆盖两种默认都失败的层。按旧实验的人为单位把全体混在一起，验证费用 33.6 小于单一默认路线 36，容易错误地认为有算法空间。

复现（Python 3.12、NumPy 2.3.5；环境安装 pandas 2.2.3）：

```sh
sha256sum -c LOCK.sha256
python -m pip download --only-binary=:all: --no-deps pandas==3.0.0 -d wheels
python -m zipfile -e wheels/pandas-3.0.0-*.whl release
python -B scout.py --new release | diff -u aggregate.json -
```
