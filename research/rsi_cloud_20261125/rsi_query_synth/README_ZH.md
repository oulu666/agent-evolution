# RSI：构造旧目录之外的查询修复

问题：旧工具仅可选单项汇总公式。对实际 SQLite 报表，新增可组合的表达式能否交付旧菜单无解的结果？新机制为反例逐步缩小候选集：把完整公式拆为两项，先缓存原子查询结果，再在新数据例上只打开仍能区分剩余候选的操作数。是否优于同语法、同预算的直接哈希分解，单独检验。

## 方法与公平预算

24 个单项按量值和过滤维度生成。新语法允许相异的两项相加或相减。共 60 个三组业务报表场景，冻结 3 张数据例用于合成，另 4 张同源生成的新表仅用来核对选定表达式。真实运行 Python 3.12.14 标准库的 sqlite3（SQLite 3.53.1）。每调用在一个例子上执行一个完整 SQL 语句；缓存不另收费，原子计算收费。每场景 42 次上限。目标来自独立 Python 行计算；生成器保证存在一个双项见证，因此不代表现实普遍性。不是历史缺陷，也未调用小模型。

| 方法 | 正确交付 | 错误 | 暂缓 | 实际逻辑查询数 |
|---|---:|---:|---:|---:|
| 旧单项菜单 | 0 | 0 | 60 | 1,440 |
| 同语法固定序穷举到预算上限 | 0 | 0 | 60 | 2,520 |
| 直接哈希分解（先计算完整首例原子） | 60 | 0 | 0 | 1,620 |
| 反例按原子再缩候选 | 60 | 0 | 0 | 1,652 |

离线在全部例子逐项核对：60/60 旧目录确实无解，60/60 有新表达式见证，未用旧策略额度不足冒充数学上无解。两项分解基线与候选同为 60/60。此面板上首例通常已充分区分，其余的原子复查只多花 32 次调用；不是新算法优势。真实数据生成过程中难度和观测权限未独立设计，**暂不晋级核心方法**。

先前工作：[Scythe](https://pldi17.sigplan.org/details/pldi-2017-papers/26/Synthesizing-Highly-Expressive-SQL-Queries-from-Input-Output-Examples) 已用抽象查询和样例约束剪枝；[分析 SQL 合成](https://pldi22.sigplan.org/details/pldi-2022-pldi/45/Synthesizing-Analytical-SQL-Queries-from-Computation-Demonstration) 也有分阶段抽象剪枝。这里的哈希关系只是已知分解思想，不主张原创或与两篇方法进行了完整复现对照。若继续，预先登记首例分不清的场景，且须在第二个查询有真实代价的权限下比较，并对读原始表后的可用强原生 SQL 定成本；不能把人为限制解释为普适效率。

复现：本目录 `python pilot.py --out results`。冻结哈希在上一级运行 `sha256sum -c rsi_query_synth/LOCK.sha256`。逐条轨迹不放入公开仓库。
