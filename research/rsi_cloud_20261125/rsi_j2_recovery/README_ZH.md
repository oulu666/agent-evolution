# J2：从历史轨迹学习事务恢复

在 CPU 训练**有限时域表格型动作价值**，不是 LLM。只用本地合成工单。真实 SQLite 初次事务要么提交，要么回滚；实验模拟回执丢失。恢复策略可以选择确认、暂缓、重试、验证后再操作，或在接口允许时做原子幂等重试。每个恢复过程最多两步；实际写入的可见结果是 SQLite 持久状态。可信的“已准备”“已落库”消息会减少不确定性，不可信消息不能保证结果。

三个学习器共享 **6,000 段实际随机探索轨迹、7,344 个状态–动作样本**；历史版保留消息；终态版移除早期消息但保留后续读回、恢复步数和公开能力；打乱版在相同可信度和幂等能力内重新绑定早期消息，不改 SQL 状态或奖励。每条测试都在新建的 SQLite 副本上闭环运行，按实际探测、重试和幂等重试计费，不只回放奖励。

| 策略 | 平衡面板 | 多已提交 | 多已回滚 | 总损失 | 追加读写调用 |
|---|---:|---:|---:|---:|---:|
| 终态奖励 + 无早期历史 | 88.90 | 73.50 | 104.96 | 267.36 | 1,608 |
| 终态奖励 + 打乱历史 | 88.18 | 75.80 | 103.58 | 267.56 | 1,562 |
| **真实历史动作价值** | **71.80** | 58.30 | 85.94 | 216.04 | 1,194 |
| 同信息原生，按源先验最小期望成本 | 72.52 | **56.00** | 87.32 | **215.84** | 1,240 |
| 同信息原生，按稳健幂等规则 | 73.34 | 65.56 | **81.24** | 220.14 | 1,061 |
| 知道真实初态的不可部署下界 | 38.50 | 23.10 | 54.56 | 116.16 | 528 |

全部策略在 1,080 个留出任务上均正确交付，**错确认、重复落库、暂缓均为零**。学习到的真实历史相对无历史对照降低约 19.2% 的假设损失；两组漂移面板均未赢当组最强原生基线。原生概率基线不知道留出条件，统一用源端 0.5 先验。终态奖励版仍看得到现场状态读回，并没有被禁止采取必要验证。所列成本是事先规定的任务单位（探测 0.14、普通重试 0.22、幂等重试 0.26），不是毫秒数；调用列不含所有策略共同承担的初始事务及离线审计，不把“确认”或“暂缓”算成 SQLite 读写。

**决定：** 可辨识的早期轨迹确实能省部分恢复操作，但同信息下原生事务/幂等实现已解决主要问题；本轮不进一步立项。丢回执是受控模拟，不是线上事故数据；能力和成本名单固定，学习与测试族共享有限状态，未验证未知 API、实测延迟或多个训练种子的稳定性。
