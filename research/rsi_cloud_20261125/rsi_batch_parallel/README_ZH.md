# 并行路线：多值回读与批处理隔离

结论：同次返回两条证据可行，但这批任务的优势由现有原生批处理与标准隔离解释。没有通过核心算法晋级。

## pandas：固定批次已足以消除歧义

对前轮四种解释，穷举 16 行布尔菜单，发现 12 对固定二探针能区分全部四种解释。例如 0011、0101 给出 00、01、10、11 四种签名。实际运行 pandas 2.2.3 和 3.0.0，包含相同的第一条反例，随后诊断两条新反例。二者的底层逻辑编辑评估同为 12 次（每个版本 3 条历史、每条 2 候选动作）。既有 worker 原生接受 JSON 数组；它与逐个子进程获得相同结果。启动 **6→2**，五次交错重复的中位用时 **1.614 秒→0.535 秒**。局部收益是分摊进程启动成本，不能声称是三倍更少的工具逻辑工作或新规划器。此固定对照是在已有实验后核查的。

## SQLite：批次必须既省初始化也保持独立

构造 48 个真实 SQLite 操作场景：四种事务内/连接级影响的组合、三个初始化规模、四种预期二位输出。每对都测试两条证据；改变的是复用初始化和还原状态方法。真值要求每条探针从独立基态出发；没有声称这些是历史缺陷。每种策略交错重复 11 次，独立再跑一批。SQL 调用计 Python 接口进入次数；初始化大量行通过一次 executemany，不等于一条引擎写入。表中的时间是第一批各案例中位数的累加，第二批方向相同。

| 策略 | 完整证据正确/48 | 连接数 | SQL 接口调用 | 用时，ms |
|---|---:|---:|---:|---:|
| 两个独立连接 | 48 | 96 | 672 | 57.63 |
| 同连接不隔离 | 24 | 48 | 480 | 29.17 |
| 只用 SAVEPOINT | 36 | 48 | 624 | 29.46 |
| 保存点和每次显式恢复设置 | 48 | 48 | 672 | 29.44 |
| 按资源类型原生隔离 | 48 | 48 | 612 | 29.44 |
| 先监测再决定恢复 | 48 | 48 | 684 | 29.43 |

SAVEPOINT 可撤销行插入；连接级 cache_size 设置会留下，第二个相同探针被污染。监测候选能减少恢复写入，但多做检查，对比原生策略多 72 个接口调用，耗时无可靠收益。一条直接按资源类型恢复的规则已足以做对。公开事实：[SQLite SAVEPOINT](https://www.sqlite.org/lang_savepoint.html) 与 [SQLite cache_size](https://www.sqlite.org/pragma.html#pragma_cache_size)。没有评估未注册资源的影响，也不能说监测能保证一般性的隔离。

保留这个基线，先把对照允许原生批处理，只有在同调用、子案例数、初始化和工具权限下有独立增益才继续。用 Python 3.12 / SQLite 3.53.1。执行本目录的 pilot.py --out results；pandas_pack.py --new 指向按同级 rsi_pandas_split 下载解包的新版本，旧版需是 2.2.3。公开不包含逐条轨迹和计时。
