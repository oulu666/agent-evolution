# 已知开发案例：拆开输入、观测与决策

使用真实 attrs 25.3.0 / 25.4.0 和 [#1427](https://github.com/python-attrs/attrs/pull/1427) 的开发案例。每版执行同样的 12 个构造请求，记录公开的 pre-init/post-init 回调与最终字段，再独立操纵可见字段或判据，不把重复分析算成新调用。不纳入盲测，不评价新算法或模型能力。

| 测试 | 只改变什么 | 测得什么 |
|---|---|---|
| I1 输入预算 | 同一端点观测，前缀预算 1→4→12 | 最终字段检出均为 0；单独的 pre-init 阳性对照为 0→2→9 |
| I2 输入策略 | 同一端点数据、同为 4 个输入，换普通／多样／边界方案 | 三个检出均为 0；实际触发条件输入数 2／4／4 |
| O1 观测点 | 固定 12 个输入，加 post-init 值或 pre-init 值 | 0/12 vs 9/12，两个观测均未对默认值误报 |
| O2 观测消融 | 保留端点、post-init、回调发生标记，只去掉 pre-init 值 | 检出 9→0 |
| R1 判据 | 不改变完整轨迹，精确相等 vs 只看端点／同为正数 | 精确值识别 9 个错误；其余两个均漏掉 9 个 |
| R2 任务语义 | 不改变完整轨迹，精确转发 vs 仅要求业务分支相同 | 有 5 个案例正确的交付决策不同；将精确规则硬套在阈值任务会误拒 5 个，将阈值规则套在精确任务会错放 5 个；只看终值分别错放 9 和 4 个 |

固定版在两种合同下均无违例；旧版三个显式默认值是阴性控制。R1/R2 是显式规则及任务义务对照，不是独立学习器的效果估计；阈值是本开发任务事先定义的业务语义，不是 attrs 的正确性规范。观察能力的结论是**在这批记录及固定端点投影**下成立，不代表其它输入空间均不可识别。

冻结协议首句的数量笔误保留原哈希：固定列表实际有三个默认值阴性对照、九个非默认值；代码按冻结列表原样运行。可用先前下载的两个真实版本重放：

```bash
python run.py ../rsi_consumer_parallel/releases > aggregate.json
sha256sum -c PROTOCOL.sha256
```

也可分别将两个 attrs wheel 用 `pip install --no-deps --target <ROOT>/attrs-25.3.0` 和 `<ROOT>/attrs-25.4.0` 方式安装，然后传入 `<ROOT>`。JSON 只保存合计，不含执行轨迹明细。
