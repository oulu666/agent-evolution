# CCET 第一轮冻结设计 · 2026-11-25

问题是一次验证通过能在多大程度上降低另一项具体任务的预计错误风险。主比较为全备用、等实际调用组中 CCET 与普通风险规划加精确缓存。次比较为相同上限下的自由追加验证。继续作为方法论文推进的门槛是两个项目上同时增加正确交付、减少错误，且不比相同预算的强基线差。若只降低校准误差或只在注入配置下获益，分别报告。

## 数据角色

拟合用此前保存的 Babel 两版周历完整执行，包括已知第 53 周案例。已有 XlsxWriter 两版时长结果仅用于独立项目上的权重校准。按版本去除重复的输入记录。拟合和校准对同版本内不同输入配对，分别保留项目、版本的依赖结构。原始 EGATV 工件只读。两个留出项目为 packaging 23.2/25.0 和 tabulate 0.8.10/0.9.0。只依据公开接口和用户显示要求预先编制任务。未看留出执行结果前冻结项目、版本、输入菜单、参数、代码、参考答案和分发包摘要。

每个项目 6 类输入模板，各取 3 组不同数字。另有使用不同参数的探针，避免重复验证目标输入。两个原始发布版本都保留。还设置两个单独的适配器配置干预，分别为忽略允许预发布选项和文字列误用数字解析。两项干预以整个故障家族留出，但其机制由研究者指定。原版结果检验版本兼容性，本研究不把 API 版本差异自动称为历史缺陷。目标项目均未参与拟合或校准。

## 算法与成本

每个输入的公开签名为普通/特殊、操作、表示形式。拟合器只看到探针与目标三个字段的相等关系，不读取目标版本、期望值、隐藏配置或返回值。按正误标签，估计同版本下探针失败的条件频率；每个有观测的版本贡献一个比例。用 Beta 半计数平滑。在 CCET 中以两项条件频率之差减去合成标准差，负值截零，形成经验性迁移强度。权重越小，探针颜色对目标风险的更新越少。跨项目校准用预设网格 0、0.25、0.5、0.75、1，按单探针条件 Brier 损失选缩放系数，平局取较小值。此后冻结。相同探针只使用一次；多个不同探针在似然更新中近似条件独立。最终 Brier 和五个等宽箱的 ECE 针对全部主工具潜在错误计分，含实际走备用或暂缓的情形。

普通风险基线复用原 EGATV 的 generic_risk 代码、wcwidth 开发状态和精确缓存；等调用组若该策略提前停止，补问一个尚未使用的探针并使用同一风险模型作终止决定。另设同开发数据的整体迁移模型、只按一般类别匹配、三个契约条件严格匹配、CCET、有备用优先切换及读取真实交付结果的事后上界。上界只给出可达到的行动结果。所有线上策略共享提案置信度、备用权限、输入、可选探针、验证代价 0.06、备用代价 0.25、暂缓损失 1 及既定后果。等实际调用主组取低后果、有备用，每个部署策略均使用两次不同探针及一次交付。自适应组可使用一次既有检查、最多一次新探针，按有无备用及任务后果分别决策。每题轮换初始探针，控制器不重复收取缓存调用成本。结果按项目、原版/配置干预分层，重复情形不作为独立故障数。

冻结的 Qwen P11 在 CPU 上为每条请求选择工具，公共参数由调用方给出，各方法共享模型提案；推理耗时单列。备用分别调用 pip 自带的另一个 packaging 实现版本及标准库 CSV 写出器，按同一目标计分。先行计算的主/备潜在结果仅供评估和上界；实际终止动作再次执行，独立核对。记录控制器与工具耗时，固定执行顺序的单机读数用于成本描述。
