# 输入—Oracle 联合合成是否值得立项？

2026 年 11 月 25 日 · ESWA 单轮准入审计

**决定：本轮关门，不立项。** 联合选择实际覆盖了更多能决定版本优先级的规则分支，但相对独立生成、NIST ACTS 或直接交付，新增盲测检出、减少误报和避免错误交付三项增量都是零。揭示后没有确认任何入组修复会改变冻结的普通字符串择高操作。因此真实缺陷召回率的分母未建立，不能用这些零把方法按检出能力排序。

## 研究对象与冻结

选取此前未参与合成器设计的 python-semver 和 python-semanticversion。两者都有合法版本号优先级比较操作，公开的 SemVer 2.0.0 第 11 条在所选提交前已发布。输入与期待关系独立于目标库。程序按固定时段、提交标题和运行时 Python 文件筛选；第一项目查到第 51 条形成三对，第二项目查完 152 条只形成一对，未递补。事前可见固定的项目和外部规范。提交说明、补丁及回归测试在执行后揭示。协议、样本、调用菜单、交付输入和程序均保存冻结哈希。

交付要求是在两个合法候选版本中选优先级高者，平局保留先提供的版本。两库均使用公开优先级比较；对象实现用严格大于和小于判断，避免把构建标记不同造成的对象身份差异混入优先级。24 个共同交付输入与所有审计菜单均无完全相同或反向相同的版本对。每个输入在四对父子版本共八个快照上执行，计 192 个情形。每种方法共享每快照最多 16 次逻辑双版本检查的预算；输入相同可复用，实际比较调用按各方法独立计。该预算与墙钟时间不同，本轮不做时延排名。

## 方法与真实基线

六个输入因子为核心版本号差异、预发布存在状态、标识符关系、共同前缀、构建元数据和操作数方向。Oracle 返回比较符号。完整判据由研究者将规范第 11 条转写为确定性比较器；简化判据从规范示例、核心数值、正式发布优先及元数据规则产生结论，不能判定时显式返回未知。未知没有通过信用。离线另用 npm 发行包内的 node-semver 7.8.1 核对全部 94 个不同的输入对，冻结比较器与其一致。

联合选择器枚举合法输入，优先选取能覆盖未见“首个决定比较结果的条款及其方向”、元数据和共同前缀条件的输入。分开生成基线在同一候选域以冻结随机种子抽取输入，再绑定同一比较器。文档驱动对照从规范中的顺序链生成直接与反向见证。这些实现检验规范已可独立执行时输入选择的边际价值。语言到 Oracle 的全面自动归纳，以及面向 Java 的 Doc2OracLL 原系统，均不在本次实测范围。[SemVer 2.0.0](https://semver.org/spec/v2.0.0.html#spec-item-11) · [NIST ACTS 工具](https://csrc.nist.gov/Projects/Automated-Combinatorial-Testing-for-Software/Downloadable-Tools) · [Doc2OracLL](https://doi.org/10.1145/3729354)

| 方法 | 每快照实际审计调用 | 覆盖的决定性条款类型数 | 老版失败且修复版通过的见证 | 修复端告警 |
|---|---:|---:|---:|---:|
| 规范原文顺序示例 | 11 | 8 | 0 | 0 |
| NIST ACTS 二路＋完整规范判据 | 14 | 7 | 0 | 0 |
| NIST ACTS 三路＋完整规范判据 | 16 | 5 | 0 | 0 |
| 文档示例导出比较关系 | 16 | 8 | 0 | 0 |
| 输入与判据分开生成并绑定 | 16 | 3 | 0 | 0 |
| 输入—判据联合选择 | 16 | 8 | 0 | 0 |

条款计数按 major、minor、patch、正式版与预发布、数字标识、数字与非数字混合、ASCII 字典序、标识符个数、优先级相等区分。示例与联合选择各覆盖八类，覆盖的具体条款不完全相同。联合选择的每一类各出现两次。ACTS 二路完整覆盖 117/117 个二因子取值组合，15 行在转换成实际调用后去重为 14 次。三路完整套件有 45 行；16 次预算前缀覆盖 225/419 个三因子组合，完整覆盖不计入主比较。

同一输入可换用简化判据。联合菜单的 16 个输入中有 8 个无法据此判定；分开生成的 16 个输入均可判定。ACTS 二路和预算内三路分别为 3/14、1/16 个未知。换完整独立判据后均可判定，仍没有盲测差异。此消融能解释“覆盖新条款还需要相应判据”，没有成功检出可分配给输入、Oracle 或二者的协同作用。

## 揭示后发现：修复改变了哪个操作？

| 提交 | 上游改动 | 与冻结入口的关系 |
|---|---|---|
| [python-semver d8813b6](https://github.com/python-semver/python-semver/commit/d8813b67a2ec5d579365f51a6d8f96d02f3fcbc3) | 更新预发布号时应产生更新的版本 | 本轮择高接收两个现成版本，没有调用版本号递增 |
| [python-semver bc41390](https://github.com/python-semver/python-semver/commit/bc41390f388d88114e8529b17fe145c5af390cbb) | 基类与子类对象之间的比较 | 本轮使用普通版本字符串，没有构造子类 |
| [python-semver 47b49ca](https://github.com/python-semver/python-semver/commit/47b49cac131c24b1d3f9046ecb62fdace0c2de9e) | 保留已弃用的比较兼容入口并调整其实现与文档 | 未证实此改动改变注册任务的数值比较结果 |
| [python-semanticversion da55cf1](https://github.com/rbarrois/python-semanticversion/commit/da55cf15dd71a0d9a839e7507e4fc69396c8326d) | npm 风格版本范围对预发布版本的匹配 | 判断一个版本是否属于范围，与比较两个版本的优先级对应不同调用 |

最后一项有执行对照。在范围 `>1.2.3-alpha <1.2.3-beta` 内查询五个上游输入，父版全部返回假；修复版对 `1.2.3-alpha.0` 和 `1.2.3-alpha.1` 返回真，其余三个仍为假。盲测使用的版本比较器在两版都能给出正确的先后次序。把范围表达式交给范围匹配入口才观察到违约。这一见证只计入揭示后解释。[配对实测](../runs_input_oracle_gate_20261125/post_reveal_range.json)

## 交付效用与论文决定

直接交付已正确完成 192/192，错误与暂缓均为 0。所有审计方法也交付 192/192，未触发暂缓或备用实现。八个快照累计审计调用：直接交付 0、规范示例 88、ACTS 二路 112、三路 128、联合方法 128。全暂缓对照为 0 个完成、192 个暂缓。独立的规范比较器若直接作为备用执行器，同样足以完成这批择高任务。主比较中没有可避免的错误交付。

本轮最有用的发现是**修复记录相关，不足以证明注册用户操作可达该修复**。事前只按主题词和文件取样确保了不看补丁，却留下了操作层错配。若未来有独立工程样本，适合在揭盲前由与生成器隔离的样本组织方确认受影响的公开操作及存在可评分的交付后果，并对生成器隐藏触发输入与预期输出。本轮不据此更换项目、补抽缺陷或重算主结果。

| 研究资产 | 本轮后的用途 |
|---|---|
| EGATV、CCET | 冻结风险更新策略，保留缓存、备用和证据迁移对照 |
| DCEP | 冻结发布规划，保留取证成本和最少检查下界 |
| 轻量契约合成器 | 冻结实现，以已有两类漏检见证补充 ISSRE 主稿 |
| 输入—Oracle 联合合成 | 完成本次候选准入审计，没有得到推动 ESWA 核心算法开发的证据 |

英文 ISSRE 主稿第 V 节已补入 python-slugify 联合参数见证和 num2words 独立拼写判据见证。它们标为独立补充队列，不改动原台账分母。现有材料支持的是对漏检原因的可复核区分，独立工程师的诊断收益仍待验证。
