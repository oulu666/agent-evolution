# 四项封存变化的主动探测必要性审计

**2026 年 11 月 26 日。** 对四项已确认的真实变化，原筛查组织者分别复核了升级端登记任务。四项均能依据首次用户请求的可见产物、公开输入和当时可用的独立要求判定。正式方法侧已经登记并可执行的完整绑定为零。按预登记顺序，进入中间反馈分支审计的案例为零。当前样本给出的工程问题是能否把已有依据公平地提供给固定与主动方法。它还没有给出必须追加探针才能完成任务判定的实例。

| 审计问题 | 单位与结果 |
| --- | --- |
| 首次请求后，组织者能否以独立依据判定本次升级端任务？ | 4/4 项变化对应的任务可判定；局部可判 0 项，材料不足 0 项 |
| 上述依据是否已绑定为当时允许的、正式方法可直接调用的判据？ | 0/4 项已有绑定；静态方法对这四项的实际正确率尚待测量 |
| 哪些任务进入“首问不可判定，是否需要依赖中间返回”的审计？ | 0 项；真实分支、分支改变最优动作和胜过全体可行预排的比例均不适用 |
| 本次产生了多少新增工具调用和用户交付？ | 对被测工具新增调用 0 次，新增交付 0 次；本次没有测量恢复效果 |

“首问可判定”允许两种证据。要确认错误，一条适用于当前任务的明确义务被实际返回违反即可；要确认满足要求，需要覆盖该任务的全部相关义务。这个判断只针对登记输入上的那次交付，不推出整个 API 在同一版本上表现一致。判定当前产物是否违约也不自动给出可用的修复。

## 为什么云端的 57 项环境记录不能替代这次审计

策略侧核对了九项已登记操作的[普通输入检查](preflight.py)，没有读取封存见证。已有检查清楚显示了操作名相同、实际判据却可以覆盖不同范围。例如 Pillow 的普通缩放与画线例子比较了小幅图像的所有像素，而模式转换例子只取一个像素；pandas 的计数与分组求和例子比较键值映射，排名例子比较数值列表；SciPy 的例子分别核对秩列表、百分位标量和 Kendall 返回中的统计量。对普通样例执行成功，并不能决定另一项用户任务的输出字段、排列要求、容差或完整产物是否全部满足。因此，57 项环境检查、四项组织者判定、正式策略交付得分分别报告。

## 对冻结和后续实验的决定

1. 继续保留固定检查用户产物、最优预排与主动方法。用升级前资料和注册用户要求独立构建共同任务包，冻结来源、适用前提、观察字段及实现摘要。组织者的逐案推导与见证对策略侧保持封存。无法事前绑定的任务如实登记，不能把实现缺口归因为任务天然需要动态反馈。
2. 正式评分仍对所有原登记任务运行同预算对照，核对静态检查实际能否判对、是否恢复、新增错误和代价。若两臂都能在第 0 步处置，提前停止并计实际调用。不扩大样本，不隐藏可用判据，不以此次结果替换主表分母。
3. 本批材料没有剩余案例需要据此作分支归因。若按原协议运行时出现可复核的不同后续请求，仍须核对真实可达反馈、固定序列的结果和实际交付。单纯出现不同的库输出不足以支持主动规划机制。

## 盲法与复核

审计口径先于复核提交于 `0999871b`。三位原筛查角色均为上下文独立的 AI，使用既有记录做只读复核，对各自样本的修复方向已有了解。这限制了把组织者判断推广到未见案例或自动判据提取的程度。协调侧仅读三方脱敏计数的总和，未取得逐案推导。汇总程序检查了分类分母、子集关系和三份不同的承诺摘要。正式揭盲时可比对私存的推导与当时允许的信息；此轮没有进行独立第三方逐案重演。六项未详审候选、一项待定记录以及九项负对照均保持原有用途。
