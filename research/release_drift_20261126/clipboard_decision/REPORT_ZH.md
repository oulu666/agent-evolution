# 真实下游验收决定：文档里的配置能否忠实复制？

**找到一个可重复的错误放行。** 在 scm-engine 用户报告指定的“Generate labels via script”配置上，Material for MkDocs 9.5.21 构建成功，页面代码文本与源文一致，复制得到的 YAML 也保持字段和类型。实际点按钮后，22 行变为 43 行，解析所得的 `label[0].script` 字符串发生变化。9.5.17 和修复版 9.5.22 接收的 22 行均与原文一致。验收要求是复制所得配置忠实于文档原文，未执行内嵌脚本，也没有将字符串变化推断为脚本业务执行失败。[用户原始报告](https://github.com/squidfunk/mkdocs-material/issues/7170) · [报告当时的下游原文](https://github.com/jippi/scm-engine/blob/50a48fad86094c3a0b07bbfd799c4bbd31b5053d/docs/configuration/examples.md#generate-labels-via-script)

| 主题版本 | 严格构建 | 页面代码文本与源文相同 | 剪贴板 YAML 结构相同 | 剪贴板 YAML 全部值相同 | 应放行 |
| --- | --- | --- | --- | --- | --- |
| 9.5.17 | 通过 | 是 | 是 | 是 | 是 |
| 9.5.21 | 通过 | 是 | 是 | 否 | 否 |
| 9.5.22 | 通过 | 是 | 是 | 是 | 是 |

仅依据前三项放行，三个版本判对两个。每版对同一按钮执行一次复制，读回系统剪贴板并对照原文，三个版本均判对。新增的一次正确判定是阻止一次错误放行，获得零次自动修复。固定端到端回归即可取得全部改善。对可改变交付渠道的 Agent，直接交付可信源块也是可用的简单对照；此次未将这种替代计为发布页面已经修复。

**算法问题缩小到了动作选择之前。** 这项证据支持研究系统能否从交付任务与成功示范中自行挑出应该检查的接收位置。例如允许观察页面和剪贴板时，需要给不同输入并保留页面不点击的对照，排除仅与页面同步变化的字段。由此生成一条固定端到端测试，在升级后重放。检验算法价值需要在未见工作流上与按动作类型查表、录制重放、观察所有可读接收位置作同预算比较。

这是从已知报告反向复现的一项开发案例。三个版本是故障前、故障中、修复后的配对条件。实验使用历史源文与高亮配置构建最小页面，使用云端 Chrome 真实复制，没有重建消费者整个容器或复跑其全部 CI。比较文本时只统一换行符并允许一个末尾换行。[运行记录](https://github.com/oulu666/agent-evolution/actions/runs/45914864894) · [原始剪贴板与判定](copy-results.json) · [实验约定](protocol.md)
