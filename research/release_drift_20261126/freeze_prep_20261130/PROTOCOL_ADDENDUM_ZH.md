## 缺口 1 · 共同资料包

每个案例一份 JSON，路径为 `packs/<case_id>.json`。同一份文件供该案例的两臂读取，不做成两份可能分叉的文件。

发布案例的两臂是 `paired_releases.json` 里的 `before` 与 `after`。slugify 的两臂是 `sample.json` 里的 `parent` 与 `rev` 提交。两臂都写入版本标识和出处。资料包还写入公开输入、公开 expected，以及允许的离线判据列表。expected 是夹具里的字段，不是已登记的 `contract_value` 表达式，除非缺口 5 的规则把它收进表达式表。

资料包不写入 `actual`、`detected_inputs`、开发实验的行，也不写入 `revealed_slugify.json` 的值。slugify 的 readme 只作为出处里的文件名和已有摘要，不升格为升级前公开文档。校准输入不升格为正式任务的升级前回归集。

装载器按案例标识找到文件并计算 SHA-256。路径规则与旧接线相同：仓库外、密封路径、允许名单和 `packs/` 以外的路径都拒绝。

关闭：六个案例都有这份文件，装载器给出摘要，两臂、版本、出处、输入、expected 和离线判据列表都在。部分关闭：只有一部分案例或一部分字段写得成。开放：没有可装载的共同文件。

## 缺口 2 · 静态序列

先只读取三个发布案例结果里 `static_info.preplanned` 的值，不读取行。slugify 没有这个键。该值只有在同时满足下列条件时才可当作方向判别里的静态序列，否则不得使用，并登记一份校准生成器：

- 它是注册候选集上的规范化请求标识序列，而不是开发探针下标。
- 选择目标是已登记先验下的 `expected_task_loss`，损失权重为 0、1、5。
- 平局先取预期在线调用更少的序列，再按规范化请求标识排序。
- 深度为整数 3，两臂的生成器、候选、先验、转移、合法动作和终端评分相同。
- 评分不依赖两端捕获库里的返回。

校准生成器只做这些事，不另做搜索算法：

- 候选是该资料包里的公开输入，标识为规范化 JSON `{"case","index"}`。停止也是合法动作。
- 合法序列是长度 0 到 3 的有序请求组，允许重复。深度 3，不剪枝，评分上限为空，因为这个有限集可以数完。
- 转移只描述调用预算：未停止且已用次数小于 3 时，把一个候选接上；否则终止。它不是结局转移。
- 终端评分函数是 `freeze_guards.expected_task_loss`。公开夹具没有给出正确、暂缓、错误上的先验质量，因此不构造质量，也不对任何序列调用这个函数来挑选胜者。
- 两臂把上述对象的同一组标识交给 `check_search_parity`。先验标识写明“没有结局质量”。这只表示两臂的设置相同。没有选出的序列，签收就绪仍为假。

枚举必须实际走完并记下条数，不只写封闭公式。开发实验的 `preplanned` 值可以写入回执，但 `development_preplanned_used` 只能在匹配成功时为真。

关闭：匹配成功并被采用，或在有结局质量的先验下选出了预期损失最小的序列且核对通过。部分关闭：生成器、合法动作、预算转移、终端评分和深度 3 的枚举都已登记，核对通过，但因为没有结局质量而没有选出序列，且开发键被明确拒绝。开放：核对仍因缺设置失败，或开发键在未证明匹配时被拿来使用。

## 缺口 3 · 适配器

适配器只在 `calibration_call.py` 里接触这三个库。`harness.py` 继续不导入它们。

现场调用使用资料包里的 `before` 或 slugify 的 `parent`，不用另一臂，因此不是配对比较。发布案例按资料包中的 URL 下载轮子，核对 SHA-256，在子进程里把该目录放到导入路径最前，再执行与 `upstream_functional_witnesses.py` 相同的公开操作：列和时长走工作簿写入，周历年走 `format_date(dt, "YYYY-'W'ww-e", locale="de_DE")`。返回值可以记入回执作为调用证据，不与 expected 比较，不计通过或失败分数。

slugify 只许检出资料包里的 parent 提交再调用 `slugify.slugify`。检出失败或该提交没有这个属性时，把异常交回 `ExtraCalls`。不许安装 PyPI 上的其他 python-slugify 来顶替。

每个可执行案例的脚本顺序不变：共享首请求使用输入 0；`probe` 使用输入 1；`verification` 使用未登记操作，适配器抛错并占用一次；`reset` 再次执行输入 0，走同一个计数器；`restore` 在进入适配器之前被拦截。没有第二条输入时不为它编造输入。

关闭：成功的在线调用进入了钉住版本的库，第四次没有进入适配器，失败调用占用了额度。部分关闭：发布库做到了这一点，slugify 因不能检出指定提交或因导入错误而没有被顶替。开放：分派的仍只是存档载荷的类型名。下载或检出失败时记下异常，不把失败写成现场调用已完成。

## 缺口 4 · 哈希冻结辅助函数

辅助函数对四组对象做规范化 JSON（键排序、UTF-8、紧凑分隔符）后取 SHA-256，再对四段摘要的规范化列表取一次总摘要。四组是：

- 可部署参数：额度 3、深度 3、空评分上限、损失权重 0/1/5、平局标识、在线目的、剪枝标识、解释器针脚状态。
- 任务注册表：六个案例标识、资料包摘要、两臂版本。
- 合理预期：各案例的表达式表。
- 处置规则：违约且已验证则交付替代，违约且未验证则暂缓，满足或未定则交付当前。

回执同时写下总摘要和这四段的名称与摘要。输入文件的 SHA-256 仍只是校准输入标识，单独列出，不冒充这次冻结。本辅助函数不勾选正式清单。

关闭：回执有总摘要和四段输入。开放：只有输入文件摘要。

## 缺口 5 · 契约表达式

只使用 `freeze_guards.contract_value` 已有的三种操作：整数取值、序列长度、非零整数倍。一条表达式只有在同时满足下列条件时才登记，并且必须是该任务的完整输出：

- 该案例每一个公开 expected 都是整数，观察模式也是这个整数，而不是浮点、字符串或列表。
- 长度只在完整输出就是某个公开输入的长度时登记。
- 整数倍只在完整输出就是公开整数输入乘以一个非零整数常量时登记。

浮点、格式串、周历年字符串、slug 字符串、布尔或字典都不登记。只约束分量、或带有未定义容差的比较，也不登记。不能表达时，该案例的表达式表为 `[]`，回执写“空规则表”，`direct_delivery` 为不可用。不为了填表而调用 `transferred_verdict`。

关闭：每个案例都有一张表；表中每一行都符合上面的规则，或者表为空且写明没有符合的公开义务。开放：没有表。若表里出现不符合规则的表达式，试跑必须拒绝写出回执。

## 缺口 6 · 正常替代值

正常值只从该输入自己的公开 expected 抄来，不从其他行、不从揭盲结果、也不用 `calibration-alt`。

- 列：expected 与捕获同为含 `visible` 和 `cell_text` 的字典时，正常值就是该字典里的对应字段。可行性仍是旧的类型条件。公开夹具没有把这两个字段绑成必须联动的不变量，因此不变量表为空。
- 时长：只对开发捕获的二元列表登记。第 0 项的正常值是该输入公开 expected 的浮点形式，且 expected 本身必须是 int 或 float。第 1 项的正常值只许是公开调用里写下的格式字面量 `[h]:mm`。档案里的标量 expected 不映射成列表。没有额外的跨字段不变量。
- 周历年字符串和 slugify 记录：expected 的形状和记录的形状不同，或不存在字段级的正常替代。不登记正常值，不用占位符充数。

用登记的正常值调用 `replay_group`。若它等于观察值，结果就是没有字段变化。这不是签收。

关闭：六个案例都有来自自身 expected 的正常值和有依据的不变量，并且重放使用的是这些值。部分关闭：列或时长做到了，其余案例明确没有登记。开放：签收路径仍靠 `calibration-alt`。

## 缺口 7 · 处置作用到案例行

只有表达式表给出裁决时，才把 `violated`、`satisfied` 或由转移规则得到的裁决送进 `disposition`。空规则表表示这条义务不能用已有词汇判定，按方向判别对不能表达的情形保留未定，不把存档实际值翻译成违约或满足。

因此空规则表的案例行只记录：裁决为未定，没有已验证替代，`disposition` 的动作为交付当前。不给该行编造正确、暂缓、错误的质量，也就不对该行调用 `expected_task_loss`。六个案例如果规则相同，回执要写明这是同一条规则，不是六个分数。

关闭：案例行有表达式给出的裁决，并且在有登记质量时计算了预期损失，同时标明是校准。部分关闭：只按空规则表做了未定处置，没有案例级预期损失。开放：案例行仍不进入 `disposition`。

## 缺口 8 · 离线计数

在校准接线里、`ExtraCalls` 之外实现三类计数，每次记下次数和耗时：

- 离线 Schema：对已有可行性谓词做一次判断，不调用库。
- 离线备用：深拷贝初态快照，不调用库。
- 初态快照复位：用该拷贝恢复内存中的快照，不调用库。

这三类不得出现在 `ExtraCalls` 的事件里。在线 `reset` 仍走额度。不修改 `freeze_guards.py`。

关闭：试跑里三类都有次数和耗时，且没有进入在线事件。开放：缺任何一类，或把它们算进了三次额度。

## 缺口 9 · 字段寻址

不许把字符串或标量包进新的字典或列表。

- 周历年捕获和档案返回若仍是字符串，保持不可寻址。
- 时长档案 `actual` 若仍是标量，保持不可寻址，也不把开发捕获回写成该标量。
- slugify 的 parent 记录若本来就是字典，则只对已有的键做 `_read`：交付记录使用它现成的 `method`、`v`、`deliver`、`calls`、`ns`；导入错误使用它现成的 `import_error`。这不是包裹。没有正常值时不做反事实签收。

关闭：三类都能在不新增结构的前提下寻址。部分关闭：只有 slugify 的现成字典可以寻址，另外两类保持开放且未被包裹。开放：要么仍然全部不可寻址，要么出现了包裹。
