## 能执行的部分

**共同资料包装载器能跑完，资料包本身不存在。** 六个案例都没有 `shared_pack` 文件。装载器只给字段做了两种标记：公开夹具里散落着，或者缺失。XlsxWriter 和 Babel 散落着的是适用版本、出处、轮子摘要、校准输入和存档 expected。注册操作、用户要求文本、旧 Schema、升级前公开文档、候选请求、判据和共用备用动作都缺失。校准输入不是正式任务的升级前回归集。存档 expected 不是 `contract_value` 的表达式。slugify 的 parent/rev 提交和 readme 摘要同样只散落在另一项公开研究的文件里；readme 没有被当成升级前文档。`revealed_slugify.json` 只有前两个标识，值没有抄进回执。任务表有 12 行。前两个标识的 parent 侧各有 43 条断言记录、24 条属性记录、48 条交付记录和 43 条检查记录；第三个标识有 23 条检查记录。这些是条数，不是通过数。

**静态序列没有可执行的正式产物。** `check_search_parity` 对深度 3、空评分上限和八个空字符串返回了 `missing or different search setting: task_pack`。没有枚举序列。三个发布案例的开发结果里存在 `preplanned` 这个键，值没有读取，也没有使用。slugify 没有这个键。

**字段组重放在两种已承认的形状上能执行。** 列的第一条捕获是含 `visible` 和 `cell_text` 的字典。时长的第一条开发捕获是浮点加字符串的二元列表。`replay_group` 拒绝了重复路径、类型不合法的替换、没有变化的替换，以及存在更小可行子集的双字段替换。单字段占位符 `calibration-alt` 使返回效果成为 `request_changed`。这是占位驱动看见字段变化后更换了请求标识，不是主动选问的证据，也不进入方法比较。占位符不是登记过的正常值，两个案例都没有登记耦合不变量。

周历年的捕获和档案返回都是字符串，没有包进新结构。时长档案里的 `actual` 是浮点标量；重放用的是开发捕获的列表，没有把列表回写成那个标量。slugify 的交付字典和导入错误都没有登记字段路径。

**处置和预期任务损失能在协议小夹具上计算。** 点质量 `(1, 0, 0)`、`(0, 1, 0)`、`(0, 0, 1)` 的损失是 0、1、5。违约且已有验证替代时交付替代，违约且没有验证替代时暂缓，满足或未定时交付当前。六个案例各调用了一次这对函数，输入都是这组小夹具，案例行没有进入函数。因此六个案例上的 0、1、5 是同一次算术核对。案例本身没有登记 `violated`、`satisfied` 或 `undetermined`。

**三次额度能在接线里拦住第四次调用。** 每个案例都是一次不计额度的共享首请求，然后探测、一次故意失败的校验、一次在线复位。第四次恢复没有进入分派函数，拦截信息是 `three additional calls already attempted`。失败的校验占用了额度。复位走的是同一个 `ExtraCalls`。单元测试另外证明备用和恢复的在线调用也走这个计数器，并且首请求失败不会被改记成额外调用。试跑的分派函数只返回存档载荷的类型名。三个库的适配器都没有接上。
