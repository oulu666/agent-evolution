## 问题

已登记的公开案例里，父版本文档中的契约能否变成可执行检查，并在已记录的第一次完整输出上把父版本边界与修复版本分开。台账里已有的现象是：完整输出常常足够判定，只看成功状态或粗字段会放过错误。那是契约绑定和观察器的问题。本轮检验绑定，不通过隐藏字段制造歧义。

## 抽取与绑定

两套实际运行的翻译共用 `Matcher.simpleMatch` 的谓词表，来源是 Jdoctor / Toradocu 3.0 的公开源码（`albertogoffi/toradocu` 的 `Matcher.java`）：`true`、`false`、`null`、`zero`、`positive`、`negative`、`nonnegative`、`nonpositive`、数值比较，以及 `== this`（接收者，不可在本记录上求值）。`empty` 能匹配正则但原函数不给出翻译，这里同样不变成检查。字符串改写只保留不依赖 Stanford 分析器的部分：`non-null` / `nonnull`、`non-empty` / `nonempty`、以 whether 开头、删除 may be / can be，以及参数义务短语 must / will（not）be 改成 is / is not。改写后连续空格折叠成一个。依赖词性标注的隐含主语规则不运行。动词按词切分，避免在单词内部匹配。

`jdoctor_pattern` 只读 Parameters / Returns / Raises（含 Sphinx、Javadoc 与 Google 风格标题）这三类标签，对应原文的 `@param`、`@return`、`@throws`。每个已翻译的 `@return` 谓词都接到记录中的完整返回值上。它不做法语标识符的词法或语义匹配，因此不是原工具的复现，也不能单独构成对 Jdoctor 的排名。

`bind` 是本轮候选。它多读标签以外的句子，并把主语绑定到记录里的值：Returns 段里主语为空或含 result / return / it / value / output，或主语的词与完整返回值字典的某个键相同。对不上则记为未绑定，不猜测字段别名。文档中的 `>>>` 示例只计数，标记为不适用于已记录调用，不执行。参数条件与异常条件需要实参，本记录没有结构化实参，两类都不可求值，不计为检出。

观察器：`status` 只看调用是否成功；`coarse` 对独立队列使用记录里已有的 `coarse`，对字典使用其中的布尔字段（没有布尔字段时与完整值相同），attrs 的粗观察是归档权限中的最终字段，完整观察含最终字段和回调；`full` 使用完整返回值。候选在完整值上的判定进入保留规则。同一谓词再投到粗观察上，只报告“完整值能分开、粗观察不能”的数量，不据此改写判定。

返回值谓词在调用抛错时没有返回值，记为 `no_return`，不把异常本身当成契约违约。只有成功状态基线把异常当成告警。

## 对照及明确不运行的工具

| 名称 | 做什么 |
| --- | --- |

| `bind` | 证据约束绑定 |
| `agora_restricted` | 只从父版本全部已记录行学习不变量，至少两行；全体为真才保留 `ok == true`、标量常数相等、字符串骨架相同。骨架把数字串换成 `0`、字母串换成 `a`。不使用修复版，也不使用哪一行是边界的标记 |

父版本上恒成立的不变量不能把父版本记为违约。修复版若偏离它，分类为方向相反，不是检出。这是在含缺陷的轨迹上学习“应当如此”的结构性后果，写在运行之前。

## 判定

独立组的第 0 行是普通输入，第 1 行是边界输入。一次检查的分类：普通输入的任一侧告警为误报；仅修复边界告警为方向相反；两侧边界都告警为双侧告警；仅父边界告警且普通输入不告警为检出；两侧边界都明确满足为双侧通过；否则无检查。一组有多条检查时，方向相反优先于误报，其次双侧告警、检出、双侧通过、无检查。

校准层按对齐后的全部行汇总：出现修复侧单独告警即为方向相反；父侧与修复侧同时告警记为双侧告警；只有父侧单独告警且没有上述两类时为检出。校准结果单列。

机械审计只服务收窄条件，不能把无检查改成检出：有 Parameters / Returns / Raises 段但全文没有任何模式翻译，记为 `catalog_gap`；有翻译但不能在记录的返回值上求值，记为 `not_evaluable`；只有文档示例，记为 `doctest_only`；都没有，记为 `doc_silent`。取回失败或源码无法解析单独标记，不算目录缺口。

## 保留、收窄或停止

只看 12 组的 `bind`。保留须同时满足：检出覆盖至少两个项目；其中至少一次检出不是 `status_only` 的检出；其中至少一次检出不是 `jdoctor_pattern` 的检出；没有方向相反；没有误报。

否则若存在方向相反或误报，停止。否则若已有检出且每一次都被 `status_only` 覆盖，或每一次都被 `jdoctor_pattern` 覆盖，停止。否则若检出只落在一个项目，收窄，理由是单项目，本轮不加新案例。否则若 `catalog_gap` 至少分布在两个项目，收窄，理由是目录缺口。其余停止。

保留只表示以后可以另写一份预登记；本拉取请求到可行性结果为止。停止则登记失败，不追加案例，也不放宽模式后再计分。
