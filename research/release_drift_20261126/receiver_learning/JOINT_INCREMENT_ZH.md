# 增量：Receiver–Oracle 联合学习的开发对照

本增量不改写冻结的 `protocol.md`，不改写已记下的 Material 复制与 jq 原始任务及计分，不勾选 11-30 清单，不打开密封标签，不开展 `question_selection`。工作基于 main [`88ca0d2090794b363c8db82a4106f2c952b69aec`](https://github.com/oulu666/agent-evolution/commit/88ca0d2090794b363c8db82a4106f2c952b69aec)，不并入 PR #12。

## 目的

不再为定位和判据合成分别堆积独立实验。本轮只验证：在有限观察预算下，接收位置 \(r\) 与闭集验收关系 \(o\in\{\texttt{byte},\texttt{full\_string},\texttt{parsed\_value}\}\) 相互约束，能否产生相对三种拆开系统的协同收益，并控制错误放行。自动生成验收检查本身不作为新颖贡献。

## 联合规则

算法维护尚未排除的组合 \(H=\{(r,o)\}\)。健康示范、任务文字给出的交付类型约束、以及下游消费证据，用于删除不一致的组合。候选仍有歧义时，在预算 1 内选择一次最有希望改善最终发布决定的合法观察；观察价值按它能否把发布决定从“接收端仍开放因而必须暂缓”推向可判定来计算，不按它能改写多少输出通道来计算。只有剩余假设足以生成验收规则时才冻结检查：接收端已唯一时，用剩余关系做一致则放行、不一致则暂缓；接收端仍不唯一或证据为空时明确暂缓。算法不得读取故障位置、版本标签或评分器使用的 \((r,o)\)。不调用语言模型，不增加第四种关系或 YAML 解析器。

## 对照系统

同一批开发任务、同一任务说明、同一预算（额外观察 1 次）下比较：

1. 固定查表 + 固定判据：可迁移动作类型查表，加上按动作或任务惯例固定的关系（导出或复制为 `full_string`，jq 风格为 `parsed_value`）。预绑定查表只作已知任务对照，不是未见工作流上的公平基线。
2. 自动定位 + 固定判据：在上述固定关系下做 `select()`、交付类型约束，必要时再用一次下游读取。
3. 固定查表 + 判据合成：可迁移查表，加上冻结短语表 `synthesize_oracle`。
4. 联合学习：上述 \(H\) 消元与按发布决定选择观察。

更强对照允许使用全部示范通道并追踪下游读取，关系集相同，但不得看真值下标或评分器的 \((r,o)\)。同时保留固定重放和两种全可读聚合。不得人为削弱任何基线或对照。

独立收益预先定义为：在违约行上，联合学习正确拦截，而三种拆开系统都没有正确拦截（误放行或暂缓不算正确拦截）。相对更强对照的额外收益单独报告；若更强对照已经覆盖全部收益，必须写明联合收益可能只是更多信息，而不是联合选择本身。

## 开发任务

三个合成场景只作机制开发，不是独立真实缺陷证据。前两个保持上一轮预览/缓存/下载与双文件案例的口径，用来显示：当短语表已唯一给出 `full_string`、只剩定位歧义时，联合学习是否退化为自动定位加固定或合成判据。第三个案例专门构造 \((r,o)\) 相互约束：暂存导出文件在三种关系下都与原文相符，真正被下游读取的导出文件只在 `parsed_value` 下相符；任务文字只有“内容保真”，短语表拒绝，惯例固定判据仍是 `full_string`。

合成反例上若有相对三种拆开系统的收益，可限时检索未见真实公开缺陷作转移验证。合取标准不放宽。只有联合学习在未见真实任务上取得其他三种方法都不能达到的收益，才能把“真正互补而非简单组合”写成结论。
