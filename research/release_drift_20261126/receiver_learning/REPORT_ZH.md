# 交付端点原型的下一次增量：封闭短语表，不是自动发现

**7a2971af 已经说明原型能在匿名读数上选出一个位置。** 那次提交冻结了 `protocol.md`、`learn.py`、`copy_task.py`、`jq_task.py` 和 `.github/workflows/learn-delivery-observation.yml`。Actions 运行 [45916565880](https://github.com/oulu666/agent-evolution/actions/runs/45916565880) 成功，回执是 [copy-receipt](https://github.com/oulu666/agent-evolution/actions/runs/45916565880/artifacts/15162726382) 与 [jq-receipt](https://github.com/oulu666/agent-evolution/actions/runs/45916565880/artifacts/15162403045)。复制任务的作业是 [140237106844](https://github.com/oulu666/agent-evolution/actions/runs/45916565880/job/140237106844)，jq 任务的作业是 [140237107074](https://github.com/oulu666/agent-evolution/actions/runs/45916565880/job/140237107074)。当时没有 `REPORT_ZH.md`。本报告不重新采集这些观察。

当时已经成立的机制是干预定位。复制任务在 Material 9.5.17 上用 `count: 41` 和 `count: 73` 做两次健康点击，记录操作前和操作后。jq 1.6 上两种模式各用 `[41]` 和 `[73]` 做两次健康运行。选择函数只看匿名位置。复制任务选出位置 1，后测消融是位置 1 和 2 并列因而暂缓。标准输出模式选出位置 3，后测消融是位置 1 和 3。文件模式选出位置 2，后测消融是位置 1 和 2。采集脚本在计分之后把这些位置标成剪贴板、页面代码、标准输出或目标文件。选择函数没有收到这些名字，也没有收到“去检查剪贴板”。

当时没有成立的是判据合成。协议写明判据、可读位置、允许的动作和工作流模式由实验者提供。`evaluate` 的参数就是 `kind` 和真实接收位置。查表直接使用那个真实位置。全可读基线没有单独计分。DOM、浏览器接口和写文件轨迹没有采集。因此不能把 7a2971af 说成已经提出并验证了自动发现接收端的算法，也不能说成已经合成了判据。能说的只是：在这条已知复制故障上，带操作前对照的位置选择，其判定与直接绑定该位置的查表一致，并且和只看构建、页面或形状的检查不同。后者是更早的剪贴板案例，不在本目录重算。

## 这次加入的代码

增量规则在 [INCREMENT_ZH.md](INCREMENT_ZH.md)。`oracle.py` 是一张封闭短语表。复制任务送入“内容保真，复制按文本”，两份示范原文都不是 JSON，得到 `full_string`。jq 送入“内容保真，按精确十进制数值和结构比较”，两份示范原文都是 JSON，得到 `parsed_value`。冻结协议的整句同时含这两种短语，编译结果是 `ambiguous_requirement`，不出检查。实验者仍负责把那一句里已经分开的两个子句分给两个任务。编译器没有从观察里决定哪一个任务用哪一种关系。

另外四条要求被明确拒绝，不进入误放行分母：只有“内容保真”是 `underspecified_relation`；“内容保真，复制按文本”但不附原文是 `no_trusted_reference`；“页面应当便于阅读”是 `unmapped_requirement`；“按精确十进制数值和结构比较”配上非 JSON 原文是 `source_incompatible`。同时写出“按文本”和“精确十进制”也是 `ambiguous_requirement`。没有实现第四种关系。

全可读基线使用同一关系，对采集向量里的每个位置做比较。全部相符才放行，以及任一相符就放行，两种都计分。轨迹机制没有实现：只包一层剪贴板接口，或按脚本里的标准输出/文件模式分支，都会和查表是同一张绑定；这次没有一张独立于已知接收位置的事件对照。

`score_artifact.py` 用上述函数重算两份回执。学习、后测消融、查表和重放的逐行判定与 7a2971af 的回执一致，差异列表为空。位置序号也与当时相同。这次的新判定只是两种全可读聚合，以及把关系从调用参数改成短语表的输出。短语表输出的关系与当时的 `text`、`json` 在这些行上等价，所以旧判定没有变。

## 计分

`truth` 是标注接收位置在所得关系下是否符合该输入的原文。误放行是 `truth` 为假却放行。正确交付保留是 `truth` 为真并且放行。暂缓不算保留，也不算误放行。复制任务有 1 行违约（9.5.21）和 2 行健康（9.5.17、9.5.22）。jq 每种模式有 3 行违约和 45 行健康。两种模式的 3 行是同一批 3 个 `test_transform/number_*.json` 在 jq 1.6 上的结果，不把 6 行数成 6 个独立缺陷。`test_parsing/y_number_*.json` 在两种版本、两种模式下都符合解析值要求，留在健康分母里。这 3 个文件是协议里的数值压力组，不是盲筛出来的缺陷；`truth` 只表示用户要求的解析值是否一致。

复制任务，分母 1 与 2：

| 方法 | 误放行 | 正确拦截 | 违约暂缓 | 保留 | 误拦截 | 健康暂缓 |
| --- | --- | --- | --- | --- | --- | --- |
| 学习 | 0/1 | 1 | 0 | 2/2 | 0 | 0 |
| 查表 | 0/1 | 1 | 0 | 2/2 | 0 | 0 |
| 固定重放 | 0/1 | 1 | 0 | 2/2 | 0 | 0 |
| 全可读，全部相符 | 0/1 | 1 | 0 | 0/2 | 2 | 0 |
| 全可读，任一相符 | 1/1 | 0 | 0 | 2/2 | 0 | 0 |
| 后测消融 | 0/1 | 0 | 1 | 0/2 | 0 | 2 |

9.5.21 的三个位置相符情况是假、假、真。学习判定为假，因为冻结位置是 1，该位置与原文不符。任一相符仍放行，因为位置 2 与原文相符；这个方法读到了位置 1 的不符，却按“有一个位置相符”放行。全部相符则三个版本都不放行，因为位置 0 始终不是原文。后测消融在示范上有两个位置，三行都暂缓，所以它既没有放行这次违约，也没有保留健康交付。

jq 标准输出与文件模式的行级计数相同。下表是每一种模式自己的 3 与 45，不是两种模式相加：

重放的 3 次误放行是 jq 1.6 相对自己的记录：记录版本与自己的全通道相符，所以放行，而这 3 行的标准输出或目标文件在解析值上已经不等于原文。同一 3 个文件在 jq 1.7.1 上解析值与原文相符，却与 1.6 的记录不同，重放把它们误拦截。学习和查表在这 6 行上与重放不同，彼此相同。任一相符的误放行来自输入文件那个位置：违约行的相符向量是假、真、假、假，输入文件仍是原文，标准输出或目标文件不是。健康行上输入文件和交付位置都相符，所以任一相符也能保留，但这不能把违约行上的放行解释掉。全部相符会因为标准错误和未使用的那个通道不是原文而拦截全部 48 行。

学习与查表在复制的 3 行、以及 jq 两种模式的全部 48 行上判定相同。单元测试里可以把查表指到别的位置，使它与学习不同；研究数据上没有发生这种分歧。迁移到 jq 之后，学习没有给出一条查表和重放都漏掉的放行路径。重放漏掉的 3 行，查表没有漏。按冻结的保留条件，查表已经追平，`question_selection` 为 `not_opened`。已知复制故障上的正确拦截只说明这条检查能跑。`ranking` 为空。不从这些分母排列方法。
