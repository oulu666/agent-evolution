**立项决定：本例未达到门槛。** MkDocs 1.5.3 构建自己的文档时，将 Python-Markdown 由 3.4.4 升至 3.5。对“已有的正文链接能否继续把读者带到原章节”这一验收决定，186 条可配对引用全部保持原目标。两个便宜的静态检查与浏览器测量一致。此次升级没有提供可供新算法挽回的错误交付。

## 为什么选择这项任务

旧版用户指南明确承诺将 Markdown 文件路径转换为网页路径，同时保留指向目标章节的锚点。首页原文就包含这类实际使用的链接。先固定消费者、任务及其项目原有验收入口，再按发布时间选择消费者发布前后相邻的稳定依赖版本。该升级是使用真实发布版在实验环境中重建的情形，没有部署日志证明 MkDocs 官方当时用这组精确依赖上线。[旧版指南](https://github.com/mkdocs/mkdocs/blob/00b648f0884244a139f034554b59a032113176f6/docs/user-guide/writing-your-docs.md#L227-L230) · [首页源文](https://github.com/mkdocs/mkdocs/blob/00b648f0884244a139f034554b59a032113176f6/docs/index.md#L32-L33) · [预登记协议](protocol.md)

## 分母和排除

旧站正文共 293 处站内片段引用。按“来源页、目标页、片段”去重后为 202 条，其中 11 条在旧构建快照里找不到对应 ID，5 条指向非标题元素。其余 186 条指向 109 个不同目标章节。旧站中缺少 ID 的引用，静态检查本身就能标出。它们的实际线上使用情况和正确目标本轮没有裁定。

逐条对照旧 Markdown 的显式地址，173 条能对应到源文件和行号。其余 13 条保留为产物级证据，生成来源未确认。来源匹配在配对计分之后离线完成，范围包括正文链接、引用式链接定义和 HTML 地址；可用 `source_evidence.py <旧版 docs 目录> <results 目录>` 复核。[源文对应记录](results/source-evidence.json)

浏览器实际访问本地 HTTP 提供的目标 URL，读取命中的标题元素和标题层级。此项测量覆盖片段导航，没有逐个模拟来源链接上的鼠标事件、键盘操作或视觉滚动。共有一个下游项目、一次依赖升级。186 条引用描述同一次发布的验收范围。

## 复现与研究决定

两个构建使用相同消费者提交、CPython 3.11 和同一份按消费者发布日期约束的依赖清单。执行器校验两个 Markdown wheel 的 SHA-256，并断言其余已安装包版本完全相同。第一次云运行因浏览器阳性对照未通过而中止；改用真实 HTTP 片段导航后，阳性和阴性对照均通过，随后完成正式配对。[历史依赖清单](results/historical-requirements.txt) · [云端运行](https://github.com/oulu666/agent-evolution/actions/runs/45913245550)

云端原始归档 SHA-256 为 `1fd16372687519b20681147aae1a99f4024e31ab4eed7e3e6cbea919905b6979`。库内一并保存两端的环境、原生测试日志、配对记录与汇总。

对这次依赖替换和这项章节兼容要求，证据支持通过验收。新增主动探针在该任务上的可挽回错误数为 0。停止在本样本上研发选问方法。如果以后启动独立研究，合适的入场证据是一条来自下游用户或维护者的具体错误验收记录，以及同一任务上固定回归和廉价静态检查仍会错误放行的配对证据。四项封存变化继续按既定协议处理。
