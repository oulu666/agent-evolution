# 公开开发实验：定位两项暂缓交付的原因

仅使用此前公开的 XlsxWriter 3.3.0、3.3.1、原 40 个宽度设置、写文本和 autofit 编辑序列。冻结依据为上轮公开协议的列任务和原执行器的预期字段。独立单位为一项历史修复，80 个配对输入—版本情形用于逐项审计。本次状态为揭示后的机制开发；不打开正式封存文件。

两因素对照。第一个因素为手写静态判据、A 的受限契约编译、B 在 A 上加入相容解释反证、C 在 B 后检查是否有资格追加真实探测。第二个因素为原动作集（无法修复则暂缓）或共享局部修复（只消除 A 列的隐藏标记）。四组使用同一首次工作簿、同一文本与可见性要求及 1+3 上限。首个工作簿只生成一次；上一轮保存了字段而未保存工作簿二进制，本次为独立读取和修复重新生成。四个验证方法并行计算，复用同一物理修复产物，向每个使用它的组合记一次离线修复。修复未通过验证时暂缓。

A 的输入为从原用户任务人工转写的两条受控语句，来源保留到公开协议和执行器；编译为限定字段与前提的可执行检查。B 对两个义务枚举四种真假组合，用实际字段排除不相容解释，查找仍可能成立的违约或满足解释。C 只对判定仍未定的实际输入检查主动分支准入；若有未定任务，单列等待真实分支验证，本轮不以模拟反馈代替。如没有触发，就报告 C 的有效样本数为零。无须给已可判定的样本强加探针。静态组保留原完整判据；另用已归档的裸交付记录做参照。

策略在 XLSX 内部读取指定列和单元格。独立评分器 openpyxl 3.1.5 回读交付物。主评分同上轮：A 列未设置隐藏且 A1 文字符合请求。另核查显式列宽是否大于零，并报告异常；不以新增条件更换原分母。修复必须使所有其他 ZIP 部件内容保持字节一致，且工作表除目标隐藏属性之外的 XML 语义一致。零修改任务原样交付。记录首次观察、误报、漏报、正确、错误、暂缓、离线耗时及线上调用；并发耗时不做速度排名。若开关修复使静态组与 A/B/C 同幅改善，收益归入恢复动作。配置与运行入口先推送后启动云作业。
