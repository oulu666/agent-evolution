## 核心推荐

第一步采用反事实经验 SFT；第二步在完全相同数据池上检验显式规则→自然表达的课程顺序；第三步仅在顽固错误仍存在时加入验证过的偏好对。保留原训练背景与成本核算。目标是提高单次完整任务成功和规则配对成功。

### 1. CoBA，EMNLP 2025 主会：打破伪相关

[正式论文](https://aclanthology.org/2025.emnlp-main.520/)。论文通过语义三元组变换生成去偏增强数据，实验主要为自然语言推断、情感分类等；它没有直接验证本项目的工具任务。

迁移方案：本项目已有精确结构，无需先让大模型提取三元组。将 File 表示为（原文件行号、文本、显示位置、选择意图），保持任务语义时独立改变显示位置，改变意图时重新计算答案。SQL 则独立生成 name/id/score 与筛选、排序、top-k、并列规则，让每条条件都在至少一例中影响正确答案。用精确执行生成标签。

先仅训练最明确的 File 干预，不把所有增强一次混入。它是受 CoBA 启发的结构化反事实 replay，不是原方法复现。首先检查顺序最小改动是否解释迁移，再确定唯一训练变量。

### 2. Can Large Language Models Generalize Procedures Across Representations?，ICML 2026：跨表达课程

[正式论文集](https://proceedings.mlr.press/v306/lin26k.html)；[方法全文](https://arxiv.org/html/2602.03542v2)。论文研究同构的代码、图与自然语言过程任务，提出先符号表示、后自然语言的两阶段 RL 课程。实验使用全参数训练，GRPO 每提示采样 16 次；不能把其成本或效果等同于我们的 QLoRA SFT。

迁移方案：对同一任务生成显式规则和自然语言两种训练输入，例如“选择最大原文件行号”与“返回最后一个匹配行”，答案和工具协议相同。先明确规则、后自然表达；测试只给正常任务提示，不额外提供答案或隐含约束。第一版仅用现有 SFT 做低成本课程假设检验。

关键对照：课程组与随机混合组使用完全相同样本多重集、各技能次数、训练预算，只改排列。仅与“自然语言单一数据”比较无法区分数据多样性与课程效应。结构化表达出现过调用阶段失败，故先统一工具协议，不能假定结构化一定更容易。

### 3. ETO，ACL 2024 主会；SimPO，NeurIPS 2024 主会：显式区分正确与实际错误

[ETO](https://aclanthology.org/2024.acl-long.409/) 从探索失败构造轨迹偏好对，使用 DPO 等优化；[SimPO](https://proceedings.neurips.cc/paper_files/paper/2024/hash/e099c1c9699814af0be873a175361713-Abstract-Conference.html) 使用平均序列对数概率和目标间隔，无需参考模型，原验证主要是聊天对齐任务。

迁移方案：在新的训练环境收集模型自身错误，按首个失败回合构造同上下文的正负响应。File 最终答案：正确末项优于复制首项；SQL 调用：验证正确的完整查询优于实际遗漏 WHERE 的查询。使用局部回合避免把正确工具调用与错误最终答案一起惩罚。

正例必须通过独立语义验证；错例需在能区分规则的数据库变体上失败。不可将省略 ASC、合法别名等语义等价写法当成负例。已有 holdout 输出只用于确定错误类别，不能直接变成训练偏好对。

建议在 SFT 基线上增设可关闭的 SimPO 项，保留正确答案 SFT 与背景 replay。只对候选响应 token 计算概率，不计算提示或工具返回概率：

`rθ(y|x)=β·log πθ(y|x)/|y|`

`Lpair=−log σ(rθ(y+|x)−rθ(y−|x)−γ)`

`L = LSFT + λ·Lpair` 是本项目拟议混合目标，非声称原论文必需该混合。λ、β、γ 在开发集固定；两候选带来额外前后向成本，不能用相同更新次数冒称相同计算量。

### 4. AgentRefine，ICLR 2025：从反馈学习修正

[正式会议论文 PDF](https://proceedings.iclr.cc/paper_files/paper/2025/file/a3cc50126338b175e56bb3cad134db0b-Paper-Conference.pdf)。核心为包含错误、环境反馈、修正的训练轨迹，并屏蔽错误回合的损失。

项目融合：数据库执行错误、调用格式错误等能获得真实环境反馈，适合构造修正轨迹。现有 `sft/dataset.py` 标注全部助手回合，直接塞入错误轨迹会训练模型重复错误；需新增按回合 supervision mask，只监督合法修正。无需把长篇自由反思作为主要训练目标。

局限：File last 和漏 WHERE 常不会触发执行器报错；完整正确答案 oracle 在真实测试时并不可用。训练可用合成 oracle，部署/测试修正只能使用允许获得的反馈。额外一次修正必须另报 repair@1、调用成本，不能当成原单次 B1 提升。

### 5. ToolRL，NeurIPS 2025 主会：细粒度工具反馈

[正式论文](https://proceedings.nips.cc/paper_files/paper/2025/hash/97c5b2707228e7e3fb67e4ecc2e0e607-Abstract-Conference.html)。论文比较工具使用的格式与正确性奖励、粒度及权重。其消融支持更重视正确性，且粗糙的两阶段奖励切换未必有益。

项目融合：先把调用合法性、表与列绑定、筛选、排序、数量、最终回答分开记录，使用执行语义而不是 SQL 字符串一致作为正确性信号。第一阶段用这些信号筛选训练对和定位失败；无需先建立完整 RL 训练栈。未来只有生成能得到足够成功样本时再测轻量 RL，避免所有 rollout 都失败而无区分信号。

这些分项信号不能允许格式高分掩盖任务失败，最终主指标仍为完整任务成功；训练 oracle 不能进入测试模型上下文。

### 6. LESS，ICML 2024：保留为经验选择基线

[正式论文](https://proceedings.mlr.press/v235/xia24c.html)。LESS 用优化器感知的低维梯度相似度进行目标数据选择，考虑 Adam 与响应长度。

项目有 LoRA 与梯度/短更新评估基础，接入成本较低，但它主要针对 loss influence。P6/P7 已暴露 NLL 与任务分数不一致，因此近期不优先。待反事实经验池已经能产生实际成功率收益，再用 LESS 作强基线，检验本项目以规则成功收益选择经验能否超越梯度选样。

## 另外三篇有用的方法

- [Simple and effective data augmentation for compositional generalization，NAACL 2024 主会](https://aclanthology.org/2024.naacl-long.25/)：增强数据的采样分布决定组合覆盖。可借鉴均匀语法规则采样，构建 SQL 约束组合池，不按照失败样本的表面频率一直复制相同模板。不得根据 holdout 分布反推训练采样。
- [PICARD，EMNLP 2021 主会](https://aclanthology.org/2021.emnlp-main.779/)：增量解析约束解码。可用其思路做当前回合的合法工具 JSON 约束，作为无需训练的工程对照；这不是直接移植原 SQL 解析器，也不能补上语义遗漏的 WHERE。保持两组同样生成预算。
- [ReVeal，ICLR 2026 会议论文](https://openreview.net/pdf?id=q56ZI1Co43)：交替生成、验证并以回合奖励训练。适合今后发展可执行验证与多轮修复。现在只有短工具链且有确定性 oracle，直接复制长程 RL 系统成本高，先借鉴执行验证原则。

## 最小实验路线

### P9-A：可比基线

先修复输入环境说明和评测分层，在新开发/最终集合上重新评价现有权重。这只校正测量，不算算法提升。若只改变推理评测，无需重训对照；若改变训练上下文或训练协议，必须给控制组相同修复，旧 P8 权重不足以单独隔离训练因素。

按环境、实体和组合结构划分 train/dev/holdout，不能把同一文件的正序放训练、逆序放测试就声称跨文件泛化。以前看过的 P8/P8.1 holdout 不作新的最终独立测试。

### P9-B：反事实 replay 的随机混合 SFT

优先 File，保持模型、背景流、first/last 次数、更新计划，唯一改动为预先选择的经验干预。先用开发集看规则响应；达到预先冻结的推进条件才开终点评价。三种子，不扩大网格。按实际 input/supervised token 和 GPU 时间报告预算，不伪装完全同成本。

### P9-C：同一池的跨表达课程

只有开发诊断支持表达迁移瓶颈才开展。B 与 C 必须包含相同显式/自然表达样本，只改顺序；若 B 的数据不包含此池，则必须另建随机混合匹配控制，不能用旧 B 硬比。三种子即可回答课程是否有效。

### P9-D：局部错误偏好

若 B/C 能学会训练题但仍重复明确错误，比较同一正例数据的 SFT 与 SFT+SimPO，额外负例和计算成本单列。需要新实现，不先同时堆进 B/C。AgentRefine/ToolRL 放到可获得环境反馈的修复实验，不和 B1 混算。

主结果：正常提示下单次完整任务成功率（每技能及宏平均）。规则检查：同一基础文件四种意图×顺序全部正确的比例；SQL 查询在独立反例数据库上的约束成功。副作用：first、median、list_tables、calendar。开发选策略，最终集只在冻结后使用；报告每种子配对差、逐题计数与总成本。

## 融合后可研究的核心算法

`开发失败 → 定位失败回合 → 生成可执行验证的反事实任务组 → 构造正例/真实错误负例 → 对照短更新 → 以规则收益选择经验 → 正式 replay → 新环境测试`

G(theta) 定义为一组相关性/不变性检查全部通过的比例。开发效用可由正常完整任务成功、G 与旧技能保持组成，各权重预先固定。候选经验按相对同状态背景更新的效用变化除以总成本选择。候选之间收益不可分辨时退回固定均衡策略，不强行宣称自适应有效。

新意需要由实验建立：在固定预算下，诊断驱动的可验证反事实经验，是否比均匀增强、单纯课程、梯度选择更能改善未见环境的规则执行。仅把几篇论文的模块拼接并不是已证明的创新。当前文献提供可检验设计依据，不提供本项目未来分数的保证。
