# 独立调用边界盲测协议
两个此前未用作开发的数据源为 blinker 和 pluggy。使用 2023-10-01 至 2025-12-31 年间可达的非合并提交，按已有研究的普通功能修复关键词、排除词和运行库路径机械筛选，各按日期取最近六条。按项目保留全部入选及失败状态。清单预封存，只显示数量。
 
仅从 blinker 1.6.2 及 pluggy 1.3.0 的公开类方法文档抽取边界。五类人工编写的条款识别规则和两个公开 API 执行适配器提供受限语法。程序从命中的文字抽取或绑定发送动作、接收者和字段，产生普通参数和组合参数。每个规则保存来源、行号与正文指纹。单操作者核查契约依据。完整性只相对于扫描的类与语法；针对输入文档设计模板，不作为未知文档解析器独立测试。
 
四组共享执行器和同一候选条件。常规测试使用普通参数与最终结果，组合测试联合切换两个或多个设置并读最终结果，契约测试在相同组合输入上读取调用记录，预算策略联合选择输入并检查记录及最终结果。每组最多三项独立场景、十五个计费公开操作；各组共用由旧版单项中位耗时估计的项目时间上限。正式比较只计上限内完成的前缀，上限内未完成项不记功。计时包含装配、事件循环、回调、观察与断言；不含导入、解包和启动解释器。每项预热后重复五轮，另测整计划前缀。时间复测不是额外独立故障。注册装饰器、构造器等测试夹具的 CPU 时间计入，逻辑操作数仅计协议列出的交互调用。匹配及装配可能增加真实费用。
 
在查看提交内容之前冻结：样本、脚本、条款、参数、断言、预算和具体计划。冻结后单独运行较早的 blinker 1.6.1 和 pluggy 1.2.0 作为留出参考版本，复核每条规则的运行与告警。参考版本是兼容性对照，任何告警须核实后才能认定为误报。每个提交两侧分别执行。主结局是冻结断言父提交失败且修复提交通过，并经上游确认对应；报告同输入最终结果一致、边界观察有见证的提交数。全菜单上限、仅有字段差异、共同失败、未能执行或预算截断分开登记。本轮使用本地哈希封存。
