# When Is a Tool Failure Detectable? An Empirical Study of Access, Budget, Observability, and Test Selection

前瞻性队列协议 v1，2026-11-24。主要轨道为 ISSRE 2027 RES。XlsxWriter 和 Babel 三例以及日历、库存、SQLite 均为开发证据。以下决定在检索本队列修复记录前写定。

**抽样框。** 选择四个未用于开发的 Python 项目，分别覆盖面向人的数量显示、表格渲染、迭代器语义和终端呈现。固定为 python-humanize/humanize、prettytable/prettytable、more-itertools/more-itertools、Textualize/rich。时间窗为 2022-01-01 至 2025-12-31（含），GitHub 已合并 PR，标题含 fix 的英文检索。每项目按创建时间降序取前 10 条，不足则全部纳入；并列按 PR 编号降序。按项目在此处的顺序轮询各项目第 1、2、…条。保留响应、总命中数、筛选理由和尝试失败。该框会漏掉标题没有 fix 的修复。

**筛选。** 纳入普通功能的、公开接口可观察的确定性偏差，能给出独立语义判据。范围为整数/日期/文本转换、有限迭代结果、表格与样式呈现。剔除文档、依赖、部署、类型注解本身、同一修复的回合并，以及需要网络外部系统、特殊硬件的情况。安全漏洞、资源耗尽和安全边界问题不在研究范围。不能从标题判断则读 PR 正文、补丁或上游测试。独立缺陷为主单位，相同根因分组，只计一次。依轮询顺序尝试，达到 12 个独立双版本确认后停止新增；其余条目标为未尝试，不作失败。若不足 8 个，保留实际结果，不放宽协议补数。

**版本与判据。** 首选上游合并提交及其第一父提交，隔离进程，使用项目源文件或可安装工件。记录精确提交。以维护者描述、上游回归断言、协议或独立计算事先规定期望。新版输出本身不能充当判据。只有旧版偏离且修复版符合期望才计作复现。分别记录正常对照和见证，观测比较在同次返回上离线进行。

**逐例冻结。** 读取上游材料可用于重建见证；在执行任何方法或查看分数前，写定该批次输入、期望和观察投影。默认序列为普通公开用法、针对公开边界的用法。有限菜单全部枚举；比较默认序与倒序的首个测试，以及相同预算下均匀选择的精确命中概率。该实验是已知缺陷上的验证协议测量，选取见证的过程有上游材料辅助，不能作为自动发现能力。

**四维配对。** A 为测试者可发出的操作和可用输入；B 区分工具原生调用和外层测试次数；O 尽量选择应用可用的粗、细两个投影，例如显示文本与布局、数量与单位、扁平值与分组；无自然可检验投影记为缺测。单纯“没有抛错”与语义检查的比较单列为弱成功信号。S 在 A/B/O 相同条件下比较选择策略。仅把在预先列出的菜单中穷尽过的差异称为菜单内不可达。逐一改变条件并保留交互，避免互斥归因。比较传统的每测试通过/失败或每缺陷检出 0/1 与四维记录能否给出不同处置建议。

**解释与决策。** 先按项目报告候选、排除、复现和有效配对数，再列每个缺陷的结果。不以输入、多个投影或版本作为独立样本，不把便利选定的四个项目当作随机项目总体。不因某个方法成绩差改变菜单。跨至少两个项目观察到同类可复核的评价变化，作为进入更充分 ISSRE 外部验证的依据，而非投稿或录用充分条件。ESEM 为备选，ESWA 的独立风险与 Agent 任务成功双门槛沿用已定战略。
