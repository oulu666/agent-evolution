# 什么时候值得先验证再选择工具？

2026 年 11 月 25 日。ESWA 方法研究，主备动作空间与探针价值审计。

**阶段决定：停止在本批环境上开发非对称 CCET。** 两个应用域的 187 条留出请求中，直接备用正确 186 条，达到主备动作集的事后正确交付上限。两域都存在用主工具节省时间的机会。YAML 中零探针的类别规则已把备用路线的批次时间降了一半以上；在两域控制探针身份后，再看实际返回没有增加正确交付上限或零错误覆盖上限。本轮未训练模型、调节风险阈值或复跑 CCET。

## 冻结设计与成本口径

本轮任务为普通 Markdown 文档渲染、显式 YAML 1.1/1.2 配置值解析。分别以 Mistune 与 markdown-it-py、PyYAML 与 ruamel.yaml 组成主备对。没有注入错误、强制延迟或备用配额。Markdown 预期来自 CommonMark 0.31.2 的公开实例，按冻结范围筛选后包括标题、列表、强调等。对比结构、文字与行内空白，忽略块元素之间只用于排版的换行。YAML 按核准的标量规则核对 JSON 类型和值。使用 PyYAML 的 CSafeLoader 及 ruamel.yaml 明确指定版本的纯 Python 安全解析器，结论对应这两个具体配置。[冻结协议与版本](action_evidence_audit/protocol.md) · [文件及规范指纹](../runs_action_evidence_20261125/lock.json) · [CommonMark 规范](https://spec.commonmark.org/0.31.2/) · [YAML 1.2 Core schema](https://yaml.org/spec/1.2.2/#1032-tag-resolution)

共有 75 条带公开答案的候选探针、72 条旧发行版开发任务和 187 条新发行版留出任务。探针、开发、测试的输入正文没有交叉。选择策略在旧版开发样本拟合，在新版本和另外的输入上计分。一个规范章节中的多个示例属于相关输入，这 187 条请求不等于 187 个独立故障。每个版本、工具、输入先暖机一次，再随机交错实测五次，六次输出一致；采用各项中位数重放部署开销。总时间包含路由、真实工具和所需探针判定。直接主备均为每题一次交付、零探针；没有补齐调用。批内缓存只复用同版本、同探针、同路线的实际返回。调用方已给出任务类别，模型推理为零。本机暖服务时间不包含装载依赖、网络或人的等待时间。[初始发行版记录](../runs_action_evidence_20261125/old.json) · [留出发行版记录](../runs_action_evidence_20261125/new.json)

## 一、主备是否各有不可替代的正确任务？

| 留出任务 | 双方正确 | 仅主正确 | 仅备正确 | 双方错误 | 直接备用正确 | 最优动作可正确交付 |
|---|---:|---:|---:|---:|---:|---:|
| Markdown，151 条 | 110 | 0 | 41 | 0 | 151 | 151 |
| YAML，36 条 | 27 | 0 | 8 | 1 | 35 | 35 |

按正确性交付，备用覆盖主工具的所有成功输入。按执行时间，Markdown 直接主/备的服务时间分别为 4.29/7.37 毫秒；YAML 为 0.68/4.67 毫秒。逐题预知两个结果及耗时、从正确者中选较快者、双错时暂缓，服务时间下界分别为 5.32 和 1.58 毫秒。该下界没有计入获得先知信息的成本。[四格表与实际动作下界](../runs_action_evidence_20261125/action_space.csv)

## 二、探针增加了哪些决策信息？

每项任务从本类探针中按输入词法相似度选择一个不同输入。决策前可知道任务类别和将被选中的探针身份，可付费获得主路、备路或两路的检查结果。对每种信息条件，事后允许同一观察桶选最有利动作。表中每格为“最多正确交付 / 要求样本内零错误时最多交付”，两项分别优化。

| 可见信息 | Markdown | YAML |
|---|---:|---:|
| 公开任务类别 | 151 / 151 | 35 / 30 |
| 类别＋探针身份，不执行 | 151 / 151 | 35 / 32 |
| 类别＋两路探针结果 | 151 / 151 | 35 / 32 |
| 类别＋身份＋两路结果 | 151 / 151 | 35 / 32 |

若只拿第一行和第三行相比，会把 YAML 的两条额外零错误覆盖计作执行反馈的收益。第二行已经获得这两条。原因可以直接验证：在同一发行版本和固定解析配置下，同一个探针始终返回同一对结果。知道身份不等于工程师事前知道结果，事后分桶也不等于新版本上可部署的映射。因此另做了下节旧版学习、新版计分。该结论只覆盖冻结的近邻探针菜单以及两条稳定工具路线。[证据上界](../runs_action_evidence_20261125/evidence_ceiling.csv)

成本复核同样使用留出轨迹。允许事后最优地按类别及探针身份查表，同时保持各域最高正确数、最少错误数，服务耗时分别为 6.33 和 1.93 毫秒。加两路结果后分桶相同；即使整批共用精确缓存、忽略路由及查表开销，执行两路探针后的下界也分别为 11.76 和 3.86 毫秒。这是结果揭示后的成本分解。[条件成本表](../runs_action_evidence_20261125/conditional_cost_bounds.csv)

## 核心案例与下一步

在显式 YAML 1.2 Core schema 下，未加引号的 0b101 不匹配规范的整数格式，任务要求保留字符串。两个库均返回数值 5。同类探针 0b11 在两路也都失败，因此有理由暂停这一项；切换实现无法修复。可见结果完全相同的桶还含其他任务，要求样本内零错误时最多交付 32/36；若直接按目标真值逐题判定则可正确交付 35/36 并暂缓一条。另一个输入 NO 在 YAML 1.2 下须保留字符串，主工具返回布尔假、备用正确。两例把“值得切换”和“切换无效”具体区分开。[逐输入观测、探针与时间](../runs_action_evidence_20261125/heldout_inputs.csv)

ESWA 暂不推进通过/失败双权重模型。下一套候选环境值得投入的条件是：在实际主备实现中能重复观察到相反方向的互补正确性，或者在相同正确数和风险下，临时探测能带来超过自身开销的净节省；同时在控制公开版本、任务条件和预定探针身份后，实时反馈仍能改变动作。未声明、可变化且行为可由真实任务独立核验的后端状态，是相较稳定解析库更合适的审计对象。当前证据足以对本批环境作出停止决定。
