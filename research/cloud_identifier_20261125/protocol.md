# 在目标答案不可见时验证字段名转换

研究问题是，Agent 收到一个字符串形式的字段名、需要转换为下划线业务字段时，能否用一次补充调用识别文档示例遗漏的错误。外部目标来自合成用户任务。每项任务事先有一个词序列，评分器据此判断交付；测试方法只接收拼写、公共词表和黑盒返回。历史发行版执行真实代码。只有核对上游行为变化与修复依据后才登记真实历史违约。

项目按支持同一操作、纯 Python、存在早期公开转换文档选入。使用 [Inflection 0.3.1 的公开 API 说明](https://github.com/jpvanhal/inflection/blob/663982efaa1a99f677e20c342a7a75dd9c041c8d/inflection.py) 和 [humps 3.0.0 的 README](https://github.com/nficano/humps/blob/c81eec145dc30e8e251ecfe007bae8d3759a6540/README.md)。两项目通用的材料支持命名转换，humps 还给出首字母缩写示例。下面的推广规则为研究者提出的待验证假设。未读取回归测试或修复内容来选输入。发行区间和 SHA 见 pins.json。最早文档版本兼作锚点，其后版本用于观察迁移，全部单列。

固定四层各 24 个任务，分别采用普通词、单缩写、相邻缩写和含词表外词。另加 4 个歧义任务，同一拼写对应两种不同用户意图。分析时单列后者。词表、任务生成顺序和常用缩写由研究者在运行前指定。版本与任务交叉不作为独立缺陷样本。

| 方案 | 能看到的信息和动作 |
|---|---|
| 文档示例 | 每版本运行全部冻结的相关字面示例，同时检查任务调用是否抛错 |
| 通用正则 | 对原输入按常见大小写边界进行两步切分，和黑盒输出比较 |
| 后缀关系 | 给输入追加 Record，原输出也应只多出 _record |
| 缩写别名 | 把词表中的大写缩写改成首字母大写，再次调用后应得到相同字段名。拼写未改变则无判定 |
| 词表唯一切分 | 在转小写后的输入上搜索分词，存在唯一分词时核对输出。多解及无解均无判定 |
| 直接备用 | 唯一分词直接交付，其余使用通用正则。所有告警方法共用这个备用动作 |

每种候选每任务最多两次工具调用。缓存按“项目、版本、实际字符串”共享。报告实际唯一调用数及各策略独立部署所需的调用数；候选无须用完预算。主指标为错误输出上的告警，另计正确输出上的误报与无判定。下游统一采用告警切备用、通过或无判定保留原输出，报告正确交付与相对裸执行的增减，同时与全量直接备用比较。项目分别统计，冻结后不据结果修改方法。

若候选比示例多检出、没有额外误报，保留机制观察；若在两个项目上都能超过直接备用且不增加错误，才进入算法研发。若仅在合成意图上改善，按任务层结果报告。若观测到版本转折，揭盲后核实相邻版本修改是否对应同一操作。重跑入口为 `python research/cloud_identifier_20261125/run.py cloud-results`。
