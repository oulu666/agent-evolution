# Qwen3-0.6B 能否利用反事实证据改变第二次日历请求？

2026 年 11 月 23 日 · TinyAgent 工具接口适配

## 实验设计

本轮把模型要做的决定缩小到两个请求之间的选择。保留 P11 seed 08 冻结检查点、上轮的 12 种边界与分页约定，以及“同一首问、最多再查一次”的约束。每个布局在调用前先确定最佳固定次问，再从其余合法请求中选一个最有机会补足它的备选。若根据反馈切换也无法改善确认数，所有组在该布局上都使用最佳预排。因而全体场景的确认率包含共同使用预排的场景，配对分支指标只计有严格优劣反转的返回。

| 组别 | 决定次问时能够看到的证据 |
|---|---|
| A | 公共任务说明、校准日程、首次请求及实际返回、两个备选请求 |
| B | 在 A 的基础上列出与实际返回相符的候选约定 |
| C | 在 B 的基础上逐个列出每种候选在两次备选请求下各自将返回哪些日期，保留重复记录 |
| D | 在 C 的基础上列出每个请求能唯一确认多少种剩余约定 |

确定性 Oracle 与四组使用同一个双请求菜单。它把每个次问的预测返回分组，在剩余约定均匀的条件下，选择单元素组最多的请求。D 能看到程序算出的两个计数，C 仍需自己从表中找出哪些行能被唯一区分。各组实际发出选中的请求，收到执行结果后都用同一个一致性核验器，仅在剩下唯一约定时提交。这个 Oracle 是封闭、无噪声实验中的精确对照。带噪声假设识别中，通过主动选择实验来区分候选已有系统研究。[Golovin、Krause 与 Ray，NeurIPS 2010](https://proceedings.neurips.cc/paper_files/paper/2010/hash/1e6e0a04d20f50967c64dac2d639a577-Abstract.html)

两套日程各有 64 个布局，每个布局都执行 12 种约定。参照组复用上轮布局。留出组保留相同的首末日组合，在每个布局中随机选一个窗口，把中间日的活动数从 1 改成 0 或 2，再更换日期，其中一半使用另一套请求与返回字段名。这使 64 个留出布局的事件计数组合全部区别于原布局。新布局仍使用同一种本地日历 API 和同一组隐藏约定。固定种子 20261123，模型推理前保存方案。没有用留出组调整提示、阈值或检查点。

每个需要模型选择的可见历史只评一次，四组看到同一历史。在每个布局内打乱候选约定顺序，每个模型决策以两种相反的请求顺序各做一次前向计算，对齐请求后平均 A/B 的对数分数差。两次展示中的选项位置因此完全平衡。表述、输入长度和信息量随证据组别变化，本实验测的是整种证据呈现的效果。

**配对分支正确率**以同一布局、同一首问、同一双请求菜单为前提。取两种均可由真实约定产生的首次返回，要求它们分别有严格且相反的最优次问。两个分支都选对才记 1 分，最优请求并列的分支排除。每一个不同的返回对只计一次。总确认数另按 12 种真实约定逐场景统计。完整识别差值按布局成对重采样 20,000 次取百分位区间。

## 四组消融结果

| 方法 | 原布局确认 / 768 | 原布局配对 / 18 | 新布局确认 / 768 | 新布局配对 / 28 | 新布局相对预排新增 / 丢失 |
|---|---:|---:|---:|---:|---:|
| 最佳预排 | 138 | 0 | 183 | 0 | 0 / 0 |
| A 原始返回 | 135 | 6 | 178 | 4 | 12 / 17 |
| B 加剩余候选 | 127 | 0 | 173 | 2 | 13 / 23 |
| C 再加预测返回表 | 127 | 1 | 170 | 2 | 10 / 23 |
| D 再加可唯一确认数 | 126 | 0 | 162 | 0 | 8 / 29 |
| 确定性 Oracle | 156 | 18 | 208 | 28 | 25 / 0 |

每个方法在每套布局上均使用 1,520 次校准调用。两套共执行 872 次模型前向计算，参数更新为零。两套中各组均无错误采用，未确认的场景均暂缓。B 是本轮同提示设计下的候选过滤对照，本轮重新组织了字段、候选次序和序列化方式。上轮 133/768 的历史成绩不参与这次组间差值计算。

新布局中，C 相对预排少确认 13 个（−1.69 个百分点，按布局配对的 95% 区间 −3.39 至 −0.26）。C 相对 A 少 8 个（−1.04 个百分点，区间 −2.34 至 +0.13），样本不支持把这个差解释为普遍退化。新布局的 28 对分支来自 17 个布局；与 A 逐对比较，C 丢掉两对，新增零对。D 比预排少 21 个（−2.73 个百分点，区间 −4.69 至 −1.17），配对 0/28。由程序使用同样计数，配对为 28/28。两项阶段门槛均未达到。可见信息的增加没有转化成这个检查点在当前投票方式下的稳定收益。

## 一个可以逐条复查的错误

留出布局 15 中，首次实际返回分别是 2086-12-07 的一条活动，或同一天的两条活动。备选查询从 12 月 15 日开始，一个截至 16 日，一个截至 17 日。

| 首次返回 | 短请求可唯一确认数 | 长请求可唯一确认数 | C 的选择 | D 的选择 |
|---|---:|---:|---|---|
| 一条 | 2 | 0 | 长 | 长 |
| 两条 | 0 | 1 | 长 | 短 |

C 两次都选了长请求，D 随返回切换，却恰好两次都选反。这对记录区分了“输出会随证据改变”和“改变方向符合证据”。它定位到当前呈现与输出之间有失配，仅凭此例不能定位到参数中的某种比较或计数能力。

## 转入生成和验证接口假设

四组消融结束后，按阶段门槛保留程序选问，启动一个不同的最小任务。新接口返回排好序的一页事件 ID。时间字段换两套名字，按两种可能字段升降序排列，隐藏页长为 3 或 5，共 16 个约定。模型看到字段名与可执行规则的输出格式，自己生成排序字段、方向和一个正整数页长或无限值，没有页长备选清单。程序只解释规定的 JSON，不执行模型生成的代码。

同一约定依次测只看 Schema、看两条记录的首次轨迹、再读八条记录的轨迹并修订上一次的提案。首次的两个时间字段同向排列，难以区分排序字段，也难以确定页长；第二份日程打乱字段间的关系，并含有多于服务上限的活动。以完整记录和真实 API 的返回 ID 验证提案，再对三份未参与提案的日程逐条比较返回 ID 及顺序。三份新日程分别有 11、7、4 个活动。评分单位为 16 个接口约定和 48 次新日程预测。另以同一规则语言做枚举，从字段、方向和观测可辨别的页长中保留能解释两次返回的规则，作为强对照。这是给定规则语言内的生成起点。

| 假设来源 | 格式可执行 / 16 | 整条规则正确 / 16 | 与两次校准均相符 / 16 | 未见日程完整预测 / 48 |
|---|---:|---:|---:|---:|
| Qwen 只看 Schema | 16 | 0 | 0 | 1 |
| Qwen 看首次轨迹 | 16 | 0 | 0 | 0 |
| Qwen 看第二次真实返回并修订 | 16 | 0 | 0 | 0 |
| 程序从相同两次轨迹筛选规则 | 16 | 16 | 16 | 48 |

跨接口共享相同输入的生成，共 22 次不同的模型生成，无参数更新。16 个真实约定都只对应一个同时符合两条轨迹的枚举结果。修订后的模型提案中，排序字段正确 2/16，升降方向正确 8/16，页长正确 0/16。模型在 8/16 个场景改动了规则，但所有 16 个场景都保留了自己的旧页长。第二次调用真实返回 3 或 5 条，模型仍给出上限 1（12 个场景）或 2（4 个场景）。因此每一条修订提案都能仅凭“实际返回条数已超过自称上限”被否决；无需动用留出日程作筛选。两阶段共用先前提案与新增轨迹，当前结果尚无法拆分历史提案与轨迹呈现各自的影响。

## 研究决策

后续保留程序负责已知规则的验证和请求比较。把小模型的下一项任务限定为**从一个具体反例提出一个此前没有的解释**。可以先故意从验证器的规则库删去一个操作，如“先按事件 ID 去重，再截取首页”，选择一份会出现重复 ID 的校准数据，使每个旧规则都被否决。一次给模型原始失败轨迹，另一次给同一轨迹和最先违规的事实。要求它提出可执行的单步扩展，程序用另一份出现不同重复位置的日程检验；另保留原规则可解释的日程，检查新解释会不会破坏原有正确预测。

要回答的是模型生成的操作能否覆盖原规则库之外的新行为。为此应与同预算的简单程序合成或规则扩展搜索比较，记录正确且能跨日程复用的新规则数、无效提案数和所用验证调用数。现有枚举器已在给定规则语言内满分，这里可把它作核验器和对照，给定的 16 个接口实验没有检验开放 API 的通用适配。
