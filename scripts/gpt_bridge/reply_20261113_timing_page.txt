二、我们现在遇到的真正瓶颈是什么？
我认为有三个。
瓶颈一：恢复能力缺乏泛化
你让模型反复练习 filter_top，它确实能做这类查询了，但其他 SQL 查询能力并没有相应提高。
原因可能是： Replay 样本覆盖的操作模式太窄，模型主要恢复了特定查询结构，而没有形成可迁移的通用能力。现在还不能确认究竟是样本身份、多样性还是训练背景造成的。
瓶颈二：不知道每种技能究竟需要复习多少
Database 的目标模式需要多条独立经验，而 Python 在较低定向比例下就已经表现很好。
原因可能是： 不同技能的初始掌握程度、退化程度、样本覆盖需求和恢复曲线不同。固定 tf25/tf50 无法针对这些差异作出决策。
瓶颈三：过量复习会干扰新技能
在 20% 预算下，Calendar 的地点去重、最晚空档、末场结束等能力出现下降。
可能原因： 有限训练更新被更多旧工具样本占据，或者旧新任务之间存在梯度冲突。但目前尚未通过机制实验区分二者。
此外，还有一个实验测量瓶颈：Calendar 部分答案对 batch 组成敏感，原标题计数任务又受到长列表计数能力限制。这些问题会影响指标可靠性，需要在新方法正式比较前控制好。

三、这些瓶颈如何推导出我们下一步的方法？
逻辑其实很自然：
发现 1：模型不是忘记整个工具，而是部分操作模式表现退化
→ 需要 Fine-Grained Skill Monitor，识别细粒度技能缺口。
￼
发现 2：不是每条经验都具有相同恢复价值
→ 需要 Experience Utility / Coverage Estimator，预测哪些经验真正值得复习。
￼
发现 3：不同技能需要的复习剂量不同
→ 需要 Adaptive Budget Controller，自动分配 Replay Token。
￼
发现 4：过量复习可能伤害新技能
→ 需要 Interference-Aware Selection，限制复习带来的新技能损失。
四、下一步最应该突破哪个瓶颈？
我最推荐优先突破「经验恢复价值预测」这个瓶颈。
因为它连接了其他所有模块。
假设模型忘记了 filter_top，历史经验池里有 100 条数据。
目前我们不知道：
• 哪 3～6 条经验最有效？
• 哪些只是重复相同模式？
• 哪些能够迁移到未见过的查询实例？
• 哪些经验会干扰 Calendar？
如果你能设计一种低成本方法，在训练之前预测每条经验或经验组合的边际恢复价值，再据此选择 Replay 数据，这就有可能形成真正的算法创新。
但首先要通过 E3-B2 排除样本身份、背景数据和训练顺序等混杂因素。
总结
核心指标： 旧技能成功率提高多少、新技能保持得怎么样、恢复能否泛化，以及花了多少 Token。
当前核心瓶颈： 定向 Replay 已经有效，但效果集中在特定操作模式；我们还不知道如何预测哪些经验真正有效，以及应该给不同技能分配多少资源。
瓶颈的潜在原因： 技能恢复需求不一致、历史经验覆盖有限、经验价值存在差异，以及新旧技能训练可能互相干扰。
下一步的创新方向： 从「人工规定复习哪些数据、复习多少」升级成「根据细粒度技能缺口、经验恢复价值和干扰风险，自主选择最有价值的 Replay」。
这就是你目前研究从实验观察走向方法创新的核心逻辑。

四、我建议你采用的实际实现方法
第 1 步：通过探针定位技能缺口
用少量独立任务检测 filter_top、filter_count 等模式的当前能力。
￼
第 2 步：通过技能标签筛选候选经验
先排除明显无关、重复或者低质量的历史样本。
￼
第 3 步：估计经验的恢复收益
可以先尝试轻量方法：计算历史经验训练梯度与薄弱技能探针梯度的对齐程度。
梯度越对齐，说明学习这条经验越可能降低该技能的探针损失。
但梯度对齐只是代理指标，不保证最终成功率提升。
￼
第 4 步：估计新技能干扰
同时检查经验更新方向是否可能增加 Calendar 探针损失。
￼
第 5 步：分配 Replay 预算
按预测的单位 Token 边际收益选经验，并限制重复样本；训练后重新测量，更新下一轮选择。
考虑你目前只有 RTX 4060，我建议先在 QLoRA 可训练参数上做梯度代理估计，而不是对 0.6B 全参数计算昂贵的影响函数。
还可以用 E3-B2 中不同经验组合的实际恢复结果，检验这个估计器能否预测收益。
五、这为什么可能成为创新？
因为现在的方法可以回答：
• 普通 Replay： 随机复习什么？
• Forgetting-Aware Replay： 哪个技能忘记了？
• 你希望实现的方法： 哪条经验能够以最少 Token 恢复这个技能，而且不会明显损害其他技能？
最后一个问题，比简单根据遗忘程度分配预算更进一步。
但是，梯度对齐、经验打分和预算优化本身都已有相关研究。你必须证明自己的估计器确实能够预测细粒度工具操作模式的跨实例恢复收益，才能形成有说服力的方法创新。
一句话总结：你要让 Agent 通过「技能缺口 + 经验覆盖 + 预测恢复收益 + 干扰成本」给历史经验打分，然后优先复习性价比最高的经验。
而我们接下来真正要研究的核心就是：
能不能在不进行完整重训练的情况下，准确预测一条历史经验对小模型工具能力的恢复价值？

为什么提前出现会有效？
可以把模型想象成一个正在学习编程的学生。

• 目标技能达到预设准确率；
• 连续几轮验证收益很小；
• 其他旧技能出现明显退化；
• Replay 预算已经用完。

6. 对我们论文有什么意义？
我建议目前这样使用两个指标：
• Σafter：主要 Exposure 指标。 衡量 Target 总共获得多少次后续优化更新。
• mom：辅助 Exposure 指标。 考虑 AdamW 一阶动量衰减，对不同 Target 的更新暴露进行加权。
你的核心科学问题实际上是：
在相同 Token 预算下，能否通过调整历史经验的插入时机，提高有效训练暴露，从而恢复更多智能体技能？
这也是为什么下一轮 dose_db1_pos127 和 dose_db4_late 非常重要。
它们能够帮助我们区分：究竟是 Target 数量在发挥作用，还是 Target 获得的更新暴露量在发挥作用。
我的建议：论文中不要把 mom 直接称为真实的有效梯度贡献，而应称为 AdamW-inspired momentum-weighted exposure proxy（受 AdamW 动量机制启发的加权暴露代理指标）。 这样科学表述更加严谨。
