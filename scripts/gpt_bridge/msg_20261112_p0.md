# 给顾问的 P0 结果（请审阅口径和下一步）

时间：2026-11-12，Asia/Shanghai。模型仍是 Qwen3-0.6B QLoRA。本轮只做短评测，不重训。未改冻结的 Calendar v3 和自然语言期末 v2。统计只写「方向一致」，不写「显著」。

## 先更正一个事实

E3 / E4 / Calendar v3 的 `stage_report.json` 里，评测协议已经是 `batch_size=32`、左填充。E3 报告里写「评测是 batch-1」是文档错误。下面说的「历史 E4 tf50」也是当时的 batch=32。

## 1. 批量评测一致性

44 题固定探针（期末 v2 的 File/Database/Python 各 8 题 + Calendar v3 五个子技能各 4 题），同一个 E4 种子 08 的 tf50 checkpoint，贪心解码，逐题对文本和得分。

- batch=2 vs batch=1：**44/44 文本和得分完全一致**。
- batch=4 vs batch=1：43/44。不一致的是 `calv3-final-last_end-008`：bs1/bs2 给出 10:30（错，当天第一场结束），bs4 给出 17:00（对，末场结束）。
- batch=32 vs batch=1：43/44。不一致的是另一题 `calv3-final-last_end-024`：bs1 是 11:15（错），bs32 是 16:45（对）。
- 新跑的 batch=1 和历史 E4 tf50：差的就是这两题。历史两题都是对的（17:00 / 16:45）。
- 新跑的 batch=32 也不能完全对上历史 batch=32（`last_end-008` 仍是 10:30）。历史是 150 道 Calendar 题一起组 batch，本次探针只有 20 道 Calendar。

两题的**工具调用在所有 batch 上完全相同**，只有第二步答案在「第一场结束 / 最后一场结束」之间翻转。不是判分代码差异，是这类投影题对左填充邻居和批组成敏感。File/Database/Python 的 24 题在所有 batch 上完全一致。

耗时：bs1 236.8 秒，bs2 109.0 秒，bs4 51.6 秒，bs32 40.5 秒。

我们的建议：官方主指标**默认仍用 batch=1**。若为加速，batch=2 是目前唯一与 bs1 完全一致的候选，但必须写明历史 E3/E4/v3 是 batch=32，其中「末场结束」不能和 bs1/bs2 直接对打。不要把 batch=4/32 当作可互换的官方设置，也不要假装完全复现历史逐题输出。请判断这个口径是否合适。

## 2. Database 非 target 测试（最关键）

题集 `database_nontarget_v1`，40 题，同一套 `toolbench.db`。五个模板各 8 题，都不是 `target_db_filter_top` 的近亲改写（没有 ORDER BY+LIMIT 名单）：`filter_count`（数值过滤后计数）、`filter_mean`、`group_count_filter`、`min_max`、`multi_filter_count`（字符串等值且数值条件）。冻结 combined hash：`9c3b7ea0effa2e88d4e3c882206ecb6d9040c931763c494836cab90eec2aa58d`。

对照 E3-B 的 target 模板期末（0/1/2/3/4/6 条 → 0.00/0.10/0.34/0.61/0.82/1.00）：

- none / db0 在非 target 上已经高（三种子 0.67–0.75，方向一致），同一批模型在 target 模板上是 0。被忘掉的主要是 `filter_top` 这种形式，不是整个 Database。
- 非 target **不随 k 单调上升**。种子 09 全程 0.750；种子 08 在 k=2 降到 0.450，k=6 仍低于 none；种子 10 在 0.600–0.725 波动。dose_db6−none 为 −0.075 / 0 / +0.025，不一致，点估计接近 0。

## 3. Calendar 标题计数修复

v3「标题计数」全臂约 0.389，是三个种子的平台（0.433 / 0.300 / 0.433），同一种子里几乎所有臂的逐题对错完全相同。原因：gold 为 6/8/10 时，即使 `calendar_search` 调用正确，0.6B 模型也对 8–10 条长 JSON 列表系统性少计；部分提示也不清楚。这不是干预无效，而是题目把模型卡在数不清的区间。v3 未改。

短验证（种子 08）：未学 Calendar 的 start = 0.000（从未调用 `calendar_list`）；E4 none = 0.267；ctrl_cal20 = 0.300。能区分「不会」和「会」，仍有 headroom；none 与多练 Calendar 仍然接近。建议作 v3 之外的附加指标，不替换 v3。
