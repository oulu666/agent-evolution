## 5. 分工具解读

### 5.1 Database：接近地板，直到定向样本足够才跃升

自然语言 Database 在 none 上三个种子全是 0，tf00 是 0.000 / 0.033 / 0.000。这与 Round 2 的观察一致：A 场景里 filter-top 在阶段开始前就不会，均匀复习几乎补不上。

按定向 Database 样本数排列：1 条 → 0.100 和 0.000（tf25 的两个种子）；2 条 → 0.567（tf25、seed 20261109）；3 条 → 0.933 和 0.867；4 条及以上 → 0.967–1.000。大约 3 条是跃升点，对应本设置里的 tf50。所以 tf25 宏平均已经升高，主要不是 Database 回来了，而是 Python（以及部分 File）先回来了；Database 的故事要到 tf50 才成立。

历史测试里的 Database 远没有这么戏剧化（none 0.389±0.038，tf00 0.522±0.139，tf50 0.478±0.171），说明模板题测到的不是同一项不会的技能。

### 5.2 Python：tf00 的高方差来自一个脆弱种子

tf00 的 Python 是 0.033、1.000、0.800，均值 0.611±0.510。无复习是 0.267、1.000、0.767。崩掉的是 seed 20261108：这个种子在 Round 2 的 none 终点上 Python 也只有 0.10，起点却是 0.967，属于真正的阶段内遗忘，而且均匀复习救不回来（0.033 甚至略差于 none 的 0.267）。

但定向成本很低：tf25 只给了 1 条 Python 目标样本，三个种子就都回到 0.967–1.000，之后不再需要更高比例。把 tf00 的宏平均拉低、方差拉大的，主要是这一个种子的 Python，外加三个种子的 Database 都接近 0。

## 7. Pareto：工作点是 tf25 与 tf50，不是 tf75

把各臂放在（旧工具 nat 修正，Calendar）平面上：

- none：0.344，0.667
- tf00：0.374，0.644 — 几乎被 tf25 支配（旧工具差很多，新工具差不多）
- tf25：0.633，0.633 — 保留明显改善，新工具均值基本保住
- tf50：0.830，0.456 — 旧工具最好（Database 终于学会），新工具付出约 18–21 个百分点
- tf75：0.737，0.278 — 旧工具差于 tf50（File 被错误标签拖累），新工具也更差，被 tf50 支配

E2 双门槛没有单一点能同时满足：tf25 的 Calendar 相对 tf00 只低 1.1 个百分点（过线），但旧工具增益 0.289 / 0.485 ≈ 60%，不到 80%；tf50 旧工具最好，Calendar 相对 tf00 低 18.8 个百分点。应按 Pareto 写，不事后改门槛，也不把 tf50 单点宣传成“最佳比例”。

若暂时把 File 从宏平均里拿掉、只看 Database+Python：tf50 为 0.956，tf75 为 0.995，两者都很高，但 Calendar 在 tf75 仍差一截。即便将来 E4 修好 File 标签后 tf75 的宏平均可能回升，新工具代价仍然更大。当前证据下，写作时的两个候选工作点是 **tf25（偏保全新工具，Database 仍弱）** 和 **tf50（偏救地板技能，新工具有稳定代价）**。选择取决于论文更强调哪一侧；也可以把比例当成方法里的可调参数，用这两点给出权衡曲线。

Round 2 A、同样 10% 预算、修正自然语言宏平均：start 0.407，none 0.341，uniform 0.352，fixed targeted 0.822。本扫描 none 0.344、tf00 0.374、tf50 0.830，和当时的 none / uniform / targeted 对齐，说明换成 v2 探针后重做的前缀没有改变主效应。本扫描的新信息是：targeted 并不是“开或关”，而是一条随比例变化的权衡曲线，而且 Database 有样本数门槛。

## 9. 局限

- 只有 3 个种子，0.6B 方差大（none / tf00 的旧工具标准差超过 0.20）。方向可以谈，显著性不能谈。
- 只做了 A 场景、一种预算。C 场景和 5% / 20% 预算是 E6、E3，还没做。
- File target 标签仍是错的，高比例臂的 File 和宏平均都受到污染。
- 实际定向比例系统性低于设定值，尤其是 tf75。
- Calendar 只有历史测试，和旧工具的自然语言主口径不对齐。若新工具的遗忘/干扰同样对格式敏感，当前的新工具代价可能被低估或高估，需要补自然语言 Calendar。
- 复习插入位置取三种计划的最小样本数，各臂都记录为 10，但实现细节仍可能有细微差别。
- 监测用的 v2 探针与最终考试相关弱，不能用本扫描的 `mv2end_*` 代替最终考试来选比例。

## 10. 对后续研究的含义

- E2 的产出是 Pareto 曲线，不是单个魔法比例。后续 E3（改预算）建议在 tf25 和 tf50 两个工作点上做，而不是先“选定 tf\* 再只跑一个”。
- E4（重建正确标签的 File 池）现在更急：不拆开标签混杂，tf50 之后 File 下行、以及 tf75 被支配，都写不干净。
- Monitor v2 的 GPU 实测表明，τ=0.8 不能直接搬到更难的 v2 探针上，否则会把所有单元标成需要复习。E5（自适应）应先做门槛重校准，不要立刻上训练。校准可以在已有的 15 个单元分数上离线做，不必先开 GPU。详见监测报告第 8 节。
- 论文主线仍然成立：预算复习有效，定向比均匀强，但必须按技能看、按自然语言考，并且承认与新工具的权衡。不要把 MMLU 或历史测试写成能力提升或“没有遗忘”。

### 8.3 关键发现：τ=0.8 不能直接搬到 v2 探针上

v2 + rule2 在三种金标准上的误报率都是 1.00，不是实现写错，而是 **15 个单元的 v2 中点分数全部低于胜任线**。90% Wilson 上界的最高值出现在 Python，也只有 0.777，仍小于 τ=0.8。于是 DEFICIENT（“水平低于胜任线”）对几乎所有单元触发；唯一例外是 C seed109 File，它还满足显著下降，被标成 DEGRADED。

四个 G_need 真负例（按最终考试并不需要复习）全部被误报，最能说明问题：

| 单元 | 自然语言终点（修正） | v2 中点 | Wilson 90% 上界 | 判定 |
|---|---:|---:|---:|---|
| A seed109 Python | 1.000 | 0.625 | 0.751 | DEFICIENT |
| A seed110 Python | 0.800 | 0.625 | 0.751 | DEFICIENT |
| C seed108 File | 0.833 | 0.438 | 0.581 | DEFICIENT |
| C seed110 File | 0.833 | 0.094 | 0.213 | DEFICIENT |

v2 题集比最终考试更难：File 换成新目录和新路径，起点常常只有 0–0.03；Database 带了改写和带过滤的均值问法，起点约 0.09–0.25；Python 加入了带“排序 / 从小到大”触发词的改写，即使最终考试已经满分，v2 中点也只有约 0.63。τ=0.8 是按最终考试的“胜任”定义预先固定的，用来卡 v2 分数就会把会做的模型也判成不足。

另外，v2 File 与最终考试 File（修正）几乎不相关。Target Fraction 扫描里，自然语言 File 可以到 0.83，同一 checkpoint 的 v2 File 终点仍是 0。因此 v2 File 目前不能当作该项技能的在线代理指标。Database 的 v2 分数与自然语言有同向关系，但被压缩（自然语言到 1.00 时，v2 大约只有 0.47–0.69）。

用“任何下降”规则去看 v2 题集，对 G_need 的召回仍是 0.36，和旧探针 + V1 一样，没有因为换题而改善“地板技能”的检出。v2 题集本身覆盖了更难的问法，但若不改判定阈值，要么全触发（rule2 + τ=0.8），要么仍主要看得到下降、看不到本来就不会（只用下降规则）。

### 8.4 对 E1 门槛和后续工作的含义

研究矩阵 E1 预先要求：v2 规则对 G_need 召回 ≥0.8、误报 ≤1/3、IE ≤30%，G_cum 召回 ≥0.8。**旧探针 + rule2 对 G_need 的召回 0.82（IE 计为未触发）或 1.00（IE 计为触发）已经过线，G_cum 召回 1.00 也过线，但误报仍是 2/4=0.50，分母太小，这一点在第 4、第 6 节已经写过，没有因为本次 GPU 评测而好转。** 换到 v2 题集之后，在不改 τ 的前提下，误报约束完全不满足。

因此：第 1 节关于“旧 monitor 没有漏掉阶段内遗忘、漏的是开始前就不会的技能”的判断仍然成立；“改规则、加入 DEFICIENT / IE”在旧探针上仍然是对的方向。但 **不能把同一套 τ=0.8 直接宣布为 v2 题集上的在线规则**，论文现在也不应强调“已经用 v2 探针做成了可靠的在线自适应”。E5 应先在这 15 个单元的已有分数上离线重校准 τ（或按工具、按子题型分别设线），再决定是否进入自适应训练。这一步不必先开 GPU。

第 6 节的局限仍然有效，并补充两条：v2 题与最终考试的难度差需要单独报告；G_need 负例只有 4 个，任何误报率都只是方向，不是稳定估计。
