四、E3 之后真正应该形成什么创新？

推荐研究主线
Coverage- and Transfer-Aware Adaptive Replay
覆盖感知与迁移收益感知的自适应经验重放
核心问题：
小模型 Agent 在持续学习新工具时，如何识别真正缺失的技能覆盖，并选择最有恢复价值的历史经验，在有限 Token 预算下恢复旧工具能力，同时保护新工具学习？
模块一：Forgetting Monitor
判断哪些工具技能真正退化。
当前 G_need 有初步基础，G_cum 还需要改进。
模块二：Experience Coverage Estimator
判断当前经验池覆盖了哪些技能，哪些操作模式仍然缺失。
这是 E3 之后值得重点开发的新模块。
模块三：Transfer Value Estimator
预测某条经验对哪些工具任务具有恢复价值。
防止模型反复学习低价值、重复性的经验。
模块四：Budget Controller
根据遗忘缺口、经验价值和 Token 成本，自动选择经验并分配预算。
最终实现动态 Replay，而不是人工指定 tf25/tf50。
这里可以形成一个完整的论文故事：
1. 发现：不同工具的遗忘和恢复规律不同。
2. 机制：恢复效果取决于技能相关经验覆盖，而非简单堆积 Token。
3. 方法：通过监测、覆盖估计和迁移预测选择经验。
4. 优化：在固定预算下进行工具级动态分配。
5. 验证：在旧技能恢复、新技能保持、跨实例泛化和 Token 效率上超过固定 Replay。

六、我对这轮 E3 的最终评价
这轮实验最有价值的不是证明 10% 比 20% 好，而是产生了三个新的科学问题：
• 覆盖问题： 为什么相同 Token 数量，覆盖更多独立目标经验能够带来更强恢复？
• 异质性问题： 为什么 Database 需要更多经验，而 Python 可能少量复习就够？
• 资源竞争问题： 为什么旧技能继续提升时，新工具的未训练子技能反而下降？
这三个问题可以自然融合成一篇论文。
我的建议是把目前的研究故事暂时定为：
From Fixed Replay to Coverage-Aware Continual Tool Learning: Understanding and Optimizing Skill Recovery in Small Language Models.
中文：
从固定经验重放到覆盖感知的持续工具学习：小语言模型中的技能恢复机制与优化。
当前最推荐的研究主线
最后提醒一个关键点：你目前最需要证明的不是「自适应一定比固定比例好」，而是：
在相同训练预算下，理解技能缺口和经验覆盖情况，是否能够比盲目增加 Replay Token 更有效地恢复模型能力？
如果 E3-B2 证实了这一点，再通过一个严格预注册的 Gap-Aware Replay 方法，在独立种子和非 target 测试集上超过固定策略，你就有了从实验现象走向方法创新的坚实基础。
