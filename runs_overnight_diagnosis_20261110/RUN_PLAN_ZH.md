# 今晚可直接启动的批量诊断

日期：2026年11月10日。

## 启动

在 `fac_tinyagent` 文件夹中双击 `START_OVERNIGHT_DIAGNOSIS.cmd`。启动窗口显示后台进程和结果位置后，可以关闭这个小窗口；计算由后台任务继续执行。

也可以在 PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Egret\Desktop\oulu\Agent Self-Evolution\fac_tinyagent\setup\start_overnight_diagnosis.ps1"
```

电脑接通电源并保持开机，避免合盖触发休眠。启动器会在运行期间请求 Windows 保持唤醒，结束后自动释放该请求，不更改长期电源设置。

## 今晚回答的问题

1. 同一个模型，在历史题和当前监测题上是否表现出不同的能力变化？
2. 对相同数值，直接说“median”和描述“排序后正中位置的值”，是否出现不同表现？差距在学习前、中点或终点如何变化？
3. 三种工具学习顺序中，旧能力在哪一步丢失、又在哪一步获得？

先完成核心诊断，再补齐完整学习轨迹。全程使用已有 Qwen3-0.6B 检查点，不进行新训练或付费 API 调用。

## 队列规模

| 部分 | 设置 | 任务评估次数 |
|---|---|---:|
| 同模型交叉评估与阶段对照 | 三个种子；学习前、保存中点、v2不复习终点、历史终点；每状态四族历史题120道＋三族监测题72道 | 2,304 |
| 中位数成对问法 | 96组新数值，每组两种表述；同样的12个模型状态 | 2,304 |
| 完整学习轨迹补评 | 将三种顺序×三个种子×四个阶段的完整历史题成绩补齐；核心部分已经包含的阶段直接复用 | 3,600 |
| 合计 | 42个模型状态，216个可独立续跑的评估单元 | **8,208** |

每道任务包含工具调用与最终答案两次生成，共16,416次逻辑生成请求，实际使用batch32批量运行。

中位数题采用七个不同整数；两种问法共享数值、工具参数和标准答案，并排除已有数据中的相同中位数实例。该题集用于开发诊断。12/24/48/96组的嵌套结果由同一次评估输出计算。

## 预计运行时间

历史batch32评估的1,440道任务累计评估耗时约12.7分钟，不含模型加载。按这一速度，8,208道任务的基础评估量级约72分钟；成对题的生成长度、42次模型加载和机器实际运行速度会增加耗时。建议为完整队列预留 **1.5—3小时**，实际时间以运行记录为准。

这个队列适合晚上无人值守，完成后自动结束。研究推进不要求把整晚算力全部用满。

## 明早查看什么

结果保存在本文件所在目录：

- `status.json`：当前进度；`status`为`completed`且`completed_units`为216时表示全部完成。
- `report.md`：逐状态成绩、成对问法成绩、前后题目的丢失与获得；运行中会分阶段更新。
- `summary.json`：完整结构化结果，含嵌套题量比较及起点→中点、中点→终点等转换记录。
- `run_*.log`：本次后台任务的运行日志。
- `launcher_status.json`：Windows启动器的结束状态和日志位置。
- `protocol.json`：模型、数据和评估程序的固定记录。

优先看三个结果：自然表述的工具选择是否更容易下降；原监测题是否遗漏同模型中的历史题下降；后半段学习是否出现新的丢失。随后用这些结果确定定向复习的内容和在线监测的检查时机。

## 续跑

如关机或意外中断，再次双击同一个启动文件即可。完成单元经校验后跳过，未完成单元重新运行。同一队列重复启动会被锁保护。

程序只在本次诊断目录内写入新结果；原训练数据、模型检查点和前轮实验报告作为输入读取。启动器和小规模GPU验证使用单独的`runs_overnight_diagnosis_20261110_smoke_v2`目录。
